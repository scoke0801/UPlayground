# 그리핀·식물 전투 AI와 스폰 연결

## 등록 및 사용

| EnemyID | 몬스터 | 이동 방식 | 스킬 |
|---|---|---|---|
| 15501 | 그리핀 | Flying, 지면 기준 저공 비행 | 15511 발톱, 15512 날개 강타 |
| 15502 | 포식 식물 본체 | Stationary | 15521 물기, 15522 독액, 15523 소환 |
| 15503 | 포식 식물 뿌리 | Stationary | 15531 휩쓸기, 15532 찌르기 |
| 15504 | 이동형 포식 식물 | Ground | 15541 물기, 15542 강한 물기 |

전투 BP·이동 BlendSpace·초기 GAS·피격 Ability는 `/Game/DataCenter/CreatureCombat`의 `BP_<EnemyID>`, `BS_<EnemyID>`, `DA_<EnemyID>`, `GA_Hit_<EnemyID>`다. 메시와 공격·피격·사망 모션은 `/Game/Art/CreatureModels`의 해당 모델을 참조한다. 기존 외형 갤러리 BP와 맵은 그대로 유지한다. `15401`은 기존 검성 보스이므로 신규 ID로 사용하지 않는다.

`DT_Enemy`, `DT_CharacterStat`, `DT_Skill`, `DT_Death`에 등록했다. `DT_StageData.Waves[].MonsterSpawnInfos`의 `MonsterId`에 위 ID와 `SpawnCount`를 지정하면 기존 `APGStageManager`에서 스폰한다. 이동형 15504는 본체가 없어도 같은 BP·AI·스킬로 동작한다.

기본 편성은 1구간 1웨이브에 이동형, 2구간 1웨이브에 뿌리, 3구간 1웨이브와 5구간 2웨이브에 그리핀, 4구간 1웨이브에 본체를 각각 1마리 배치한다. 기존 적 한 마리씩을 교체하여 웨이브 총수·지연·보상·보스 편성을 유지한다. `MonsterVariationRoster.compose`도 이미 등록된 신규 편성을 유지한다.

## 실행과 튜닝

- 공통 역할 BT와 GAS 패턴 실행을 재사용한다. `FPGEnemyDataRow.Mobility`가 지상·공중·고정형 이동을 구분한다. 고정형은 이동 컴포넌트를 비활성화하고 접근·후퇴 요청을 차단한다.
- 공중형은 `MOVE_Flying`에서 이동 입력과 캡슐 충돌을 사용한다. 지형을 검사하여 `FlightHeight`(기본 60cm)를 유지하고 바닥이 없는 방향으로 진행하지 않는다. 현재는 지면 위 저공 추격이며 입체 내비게이션이나 이착륙 상태 머신은 아니다.
- 본체의 15523은 1.5초 예고 후 이동형 2마리를 소환한다. 쿨다운 12초, 본체당 생존 상한 4마리, 반경 350cm다. 도달 가능한 NavMesh와 빈 캡슐 공간을 확인하며 제한된 시도 횟수 안에서만 스폰한다. 기존 `OnSpawned` 메시지로 스테이지의 `bCountSummonedEnemies` 정책을 따른다.
- 소환체는 생성 완료 전부터 드랍을 비활성화한다. 본체 제거 시 소환체를 정리한다. 단독 웨이브 스폰의 이동형은 기존 시드 기반 드랍 경로를 사용한다.
- 예고 중 취소·사망은 공통 패턴 타이머 정리를 사용한다. 소환은 피해를 발생시키지 않으며 기존 회복 단계로 복귀한다. 상한 도달 시 AI 선택·직접 실행 모두 소환을 거부한다.
- 수치 원본은 `Tools/Validation/Data/CreatureCombat.json`이다. 피해·예고·회복·쿨다운·공격 선택·스탯은 데이터에서 조정한다.

```powershell
& 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/ThirdParty/Python3/Win64/python.exe' Tools/Validation/RunCreatureCombat.py --apply --render
```

적용 전 관련 패키지를 `Saved/QA/CreatureCombat_<시간>/backup`에 백업한다. `transaction.json`과 `before.json`에 원본을 기록하고, 무관한 테이블 행과 웨이브 총수를 새 프로세스에서 비교한다. 실패 시 자동 원복은 하지 않으며 수정 후 재실행하거나 기존 `PlayableCharacterTransaction.restore`로 해당 실행의 백업을 복원할 수 있다. 생성 Content는 기존 저장소 제외 정책을 따른다.

## 검증 기록

- UE 5.8 Development 에디터 빌드 통과. 기존 엔진 API 폐기 예고 및 모듈 순환 참조 경고는 남아 있다.
- `CreatureCombat_20261010T051534`: 적용·새 프로세스 재로드 통과. 4종 BP·AI·이동 보간·전용 스켈레톤 몽타주·소환 연결·기존 테이블 행 보존을 확인했다.
- 같은 실행의 `Automation/index.json`: PG 테스트 56개 통과(일반 성공 46, 경고 포함 성공 10, 실패 0). 소환 ID·생존 상한·버스트 수·반경의 잘못된 입력 검사도 포함한다.
- 공통 `ValidateRoguelikeMVP.py` 에셋 검사 통과(content schema 5). 기존 플레이어 스킬·보스·드랍과 신규 웨이브를 함께 검사했다. 역할 매핑과 P0/P1의 추가 스킬 허용 목록에는 신규 정의의 ID만 추가했다.
- 전투 BP·렌더 검사 `CreatureCombat_20261010T052534`: 적용·재로드·실전 PIE 검사가 종료 코드 0으로 통과했다. 공격 8개 모두 실제 GAS 피해를 발생시키고 9개 시전 모두 해당 모델의 몽타주를 재생했다. 소환 검사의 플레이어 생명력 변화에는 생성된 이동형 식물의 공격이 포함되므로 본체 소환 스킬의 직접 피해로 해석하지 않는다.
- 마지막 격리 렌더 실행의 이동 검사에서 그리핀은 약 134cm 이동·55cm 상승, 이동형은 약 513cm 이동했고 본체·뿌리의 위치 변화는 0이었다. 비행 높이는 프레임·지형에 따라 조절되므로 이 수치는 해당 검사 구간의 관측값이다.
- 소환 생존 상한 4마리, 쿨다운 이후 상한 거부, 한 마리 제거 후 재시전 가능, 예고 취소 후 추가 생성 없음, 본체 제거 시 잔여 소환체 정리를 확인했다.
- 기존 스테이지 매니저가 1~4구간 첫 웨이브에서 각각 15504·15503·15501·15502를 생성하는 것을 확인했다. 5구간 추가 편성은 데이터 재로드·총수 보존 검사 범위다.
- 공격 9장과 비행 1장의 1280×720 렌더를 생성했다. 소환체와 다른 검사 액터를 숨긴 격리 공격 렌더로 그리핀·본체·뿌리·이동형의 외형을 확인했다. 검사 도중 만든 배치 액터와 카메라는 종료 시 제거하며 RogueArena를 저장하지 않는다.
- 최종 스킬 분류 적용 `CreatureCombat_20261010T053203`: 15523의 `SkillType=SummonEnemy`를 명시한 뒤 적용·재로드·동일 실전 검사 전체를 다시 통과했다. 이 실행의 `transaction.json`은 VERIFIED다.

검사 실행 전 변경된 C++를 UE 5.8 Development 에디터 대상으로 빌드해야 한다. `RunCreatureCombat.py`는 빌드를 자동 실행하지 않는다. 첫 신규 등록 전의 원본 테이블 백업은 `CreatureCombat_20261010T051534`, 마지막 BP 이름표·피드백 설정 전 백업은 `CreatureCombat_20261010T052534`다.
