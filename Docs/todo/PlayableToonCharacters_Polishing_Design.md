# 툰 플레이어와 P09 캐릭터 폴리싱 설계

작성일: 2026-10-05. 상태: 구현 진행 중. P0 재생성 안전장치와 P1 부착 기반의 변경·검증 범위는 [1차 구현 기록](PlayableToonCharacters_Polishing_Implementation_Report.md)을 따른다. 단계별 전체 수용은 아직 완료하지 않았다.

이 문서는 플레이어 7종과 P09 몬스터 4종의 손 그립, 발 고정, 헤어·의상 물리를 개선하기 위한 후속 구현 기준이다. 기존 전투·장비·저장 경로를 유지하고 표시 포즈를 보정한다. 작업 순서는 보정 데이터 보존, 한손검 그립, 대표 캐릭터 발 보정, 전체 확장, 선택적 보조 물리, 패키지 성능 검증이다.

현황의 근거는 [기존 구현 보고서](PlayableToonCharacters_Implementation_Report.md), 실제 C++·생성 도구, Epic UE 5.8 공식 문서다. 아래 신규 타입·필드·명령 이름과 수용 수치는 설계 제안이며 현재 구현된 API나 측정 결과를 뜻하지 않는다. 이번 문서 작성에서는 빌드·에디터 실행·바이너리 에셋 검사·성능 측정을 수행하지 않았다.

## 목표와 범위

쿼터뷰 전투에서 무기가 손에서 뜨거나 발이 끌리는 현상을 줄이고, 필요한 부위에만 보조 움직임을 부여한다. 외형 추가가 전투 로직 복제나 캐릭터별 C++ 분기로 이어지지 않도록 보정값을 데이터화한다. 장비 교체 후에도 무기 부착과 공격 가독성이 유지되는 것을 목표로 한다.

| 구분 | 대상 |
|---|---|
| 플레이어 | Bokusei, LianLian, Honoka, Hichi, Siuha, Lili, Nenmir |
| 몬스터 | P09 Female, Male, Female Armor007, Male Armor007; 적 ID 15201–15204 |
| 우선 구현 | 생성 데이터 보존, 한손검 부착·손가락 보정, 이동·대기 접지, 표시용 품질 설정 |
| 후속 확장 | 양손 무기 보조손 IK, 헤어 본 물리, 대표 의상 Chaos Cloth |
| 별도 작업 | 고유 스킬·밸런스, 신규 몬스터 역할, 웨이브 편성, 전면적인 스켈레톤 재임포트 |

캡슐, GAS 효과, 공격 프로필, 이동 거리, 피해와 쿨다운의 권한은 기존 경로에 둔다. 표시 포즈에서 게임플레이 루트 모션이나 전투 Notify를 중복 발생시키지 않는다. 표시 무기 위치가 달라졌을 때 실제 피해·VFX 기준점이 영향을 받는지는 구현 전 호출 경로를 추적하고 회귀 검사한다.

## 현재 구조와 차이

| 근거 파일 | 확인한 현재 동작 | 필요한 확장 |
|---|---|---|
| [외형 데이터](../../Source/PGData/DataAsset/Character/PGCharacterAppearance.h) | 메시, 리타게터, 부위, 본 매핑을 저장 | 장비별 오프셋, 손·발 보정 설정, 부위별 포즈 방식 |
| [외형 컴포넌트](../../Source/PGActor/Components/Rendering/PGCharacterAppearanceComponent.cpp) | 원본 메시 숨김, 표시 메시 생성, 장비 Anchor 연결 | 보정 데이터 전달, 부위 평가 순서, 초기화·실패 복구 |
| [표시 AnimInstance](../../Source/PGActor/Components/Rendering/PGAppearanceAnimInstance.cpp) | 네이티브 Retarget 노드 출력, P09 이동 단위 복원 | 보정 노드 연결, 스냅샷 입력, 커브 전달 검증 |
| [생성 도구](../../Tools/Validation/ConfigurePlayableCharacters.py) | IK Goal 없는 체인, Pelvis Motion·FK Chains 생성 | IK 설정과 폴리싱 원본 데이터의 결정적 재적용 |
| [실행 도구](../../Tools/Validation/RunPlayableCharacters.py) | inspect/configure/validate/runtime/automation 경로 | 연속 포즈 측정, 전후 비교, 부하 시나리오 |

현재 `configure`는 `remove_all_ops()`, `reset_retarget_pose()`, 체인 재생성과 자동 정렬을 수행한다. `Parts`와 장비 본 매핑도 다시 기록한다. 에디터 수동 수정만으로 보정값을 유지할 수 없으므로 생성 정책 변경을 모든 에셋 튜닝보다 먼저 수행한다.

원본 메시는 `AlwaysTickPoseAndRefreshBones`로 평가하며 업데이트 빈도 최적화를 끈다. 표시 메시에는 원본의 틱 선행 조건이 있다. 동일 스켈레톤 부위는 Leader Pose, 다른 헤어 리그는 Head 본 부착을 사용한다. 현재 생성되는 부위에는 독립 보조 AnimBP를 지정하지 않는다.

기존 보고서의 PG 테스트 45개 통과는 당시 검증 기록이다. 본 설계의 IK·물리 품질이나 현재 작업 트리의 새 실행 결과를 보증하지 않는다.

## 보정 데이터와 재생성

### 데이터 소유권

런타임 설정은 기존 `UPGCharacterAppearance`에 필요한 구조체를 추가한다. 여러 외형에서 공유할 실제 데이터가 생기기 전에는 별도 관리 시스템을 만들지 않는다. `PGData`가 설정을, `PGActor`가 평가·컴포넌트 수명을 소유한다. `PGAbilitySystem`에는 외형별 분기를 추가하지 않는다.

| 제안 데이터 | 주요 필드 | 의미와 기본 동작 |
|---|---|---|
| `FPGAppearanceGripProfile` | 장비 유형 키, 원본 소켓 키, 타깃 본/소켓, `GripOffset`, 손가락 포즈, 가중치 커브 | 항목 없으면 기존 Anchor 계산 사용 |
| `FPGAppearanceFootSettings` | 좌우 발·발끝·골반 본, 발바닥 높이, Trace 범위·채널, 높이·회전 한계, 블렌드 시간 | 기본 비활성, 누락된 체인은 보정 생략 |
| `FPGAppearanceQualitySettings` | IK·물리 최대 LOD, 거리 범위, 보간 시간, 활성 부위 상한 | 표시용 작업만 단계적으로 축소 |
| `EPGAppearancePartPoseMode` | Legacy, LeaderPose, CopyPose, BoneAttached | 기존 직렬화 데이터는 Legacy로 현재 규칙 유지 |
| `FPGAppearancePart` 확장 | PoseMode, 보조 AnimClass, 선택적 Physics Asset | 독립 평가가 필요한 부위만 사용 |

위 타입과 필드는 구현 시 기존 장비 유형·GameplayTag 정의를 우선 재사용한다. 새로운 무기 분류 체계를 병렬로 만들지 않는다. Chaos Cloth의 별도 컴포넌트·에셋 참조는 본 물리 파일럿 후 필요할 때 추가한다.

`GripOffset`은 타깃 부착 본/소켓 기준 로컬 Transform으로 정의한다. 길이·Trace 설정은 UE 월드 센티미터 기준으로 저장하고 컴포넌트 스케일을 반영해 변환한다. 각 필드의 좌표계·단위를 에디터 설명에 표시한다. P09의 FBX 루트 스케일을 단순히 100으로 나눠 모든 설정에 적용하지 않는다.

### 생성과 튜닝 절차

추적 가능한 폴리싱 설정 파일을 생성 원본으로 두고, 생성된 DataAsset·IK Rig·Retargeter는 실행 결과물로 취급한다. 설정 파일 위치는 `Tools/Validation/Data/PlayableCharacterPolish.json`을 제안한다. 원본 설정에는 스키마 버전, 외형 ID, 본 매핑, 리타게팅 포즈 보정, 필요한 Op와 순서, 커브 이름, 손·발·부위 설정을 포함한다. 복잡한 포즈·물리 에셋은 참조 경로와 재현 가능한 제작 원본을 관리한다.

1. 기존 설정과 대상 패키지를 검사하고 변경 예정 목록을 출력한다.
2. 생성 도구 소유 필드와 수동 에셋의 경계를 정한다. 알 수 없는 수동 Op·필드를 발견하면 해당 에셋 저장을 건너뛰고 충돌을 보고한다.
3. 변경 대상 패키지와 설정 원본을 백업한다.
4. 기본 리그를 생성하고 폴리싱 설정을 재적용한 뒤 검증·저장한다.
5. 새 에디터 프로세스에서 재로드하고 참조와 의미상 설정을 비교한다.
6. 동일 입력으로 다시 생성해 본 매핑·포즈·Op·보정값이 동일함을 검사한다. 바이너리 해시 일치만으로 판단하지 않는다.

에디터에서 조정한 값을 원본 설정으로 내보내는 기능을 함께 제공한다. 내보내지 않은 수정은 변경 감지 대상으로 남긴다. 저장 실패 시 백업과 매니페스트로 대상 패키지를 복원하고, 부분 성공을 완료로 보고하지 않는다. 기존 Portrait 등 폴리싱과 무관한 외형 필드는 보존한다.

현재 `/Content` 제외 정책을 고려해 별도 체크아웃에서 원본 아트와 튜닝 에셋을 확보하는 경로를 기록한다. 에셋 이름만 남아 있고 제작 원본을 복구할 수 없으면 재생성 수용 실패다.

## 표시 포즈 평가 구조

기본 경로는 기존 네이티브 `UPGAppearanceAnimInstance`와 Proxy를 확장하는 방식이다. 스켈레톤마다 전체 전투 AnimBP를 복제하지 않고, 리타게팅 뒤에 공통 보정 노드를 연결한다. 보조 부위에는 필요한 경우에만 별도 AnimBP를 사용한다.

주 메시 평가 순서는 다음과 같다.

1. 원본 전투 AnimBP와 몽타주를 평가한다.
2. Retarget Pose From Mesh를 평가한다. 선택한 외형에 한해 리타게터 내부 IK를 적용한다.
3. 기존 P09 루트→골반 이동 단위 복원을 수행한다.
4. 표시 포즈의 골반·발 지형 보정을 수행한다.
5. 주손 기준 무기 Transform을 계산하고 보조손 IK와 손가락 그립을 적용한다.
6. 필요한 주 메시 보조 본 물리를 적용한다.
7. 최종 표시 포즈를 부위에 전달하고 독립 부위 물리를 평가한다.

이 순서는 설계 기준이다. 리타게터 내부 IK가 P09의 이동 단위 복원 이전에 실행된다는 점은 선행 검증 대상이다. 실패하면 P09는 검증된 FK 출력과 스케일 복원을 유지한 채 후단 발 IK부터 적용한다. 기존 보정을 삭제하거나 전체 자손 본 이동에 확대하지 않는다.

월드 Trace와 상태·장비 조회는 게임 스레드에서 수행하고 Proxy에 값 스냅샷을 전달한다. `Evaluate_AnyThread`에서는 월드 조회, 장비 Actor 탐색, UObject 변경을 수행하지 않는다. 프레임마다 본 이름 탐색·에셋 로딩을 하지 않고 초기화 때 필요한 본 인덱스와 참조를 캐시한다. LOD의 Required Bones 변경 시 본 캐시는 다시 구성한다.

지면 Trace는 마지막으로 확정된 발 위치와 현재 캐릭터 이동을 바탕으로 샘플링한다. 이전 포즈 사용에 따른 오차는 급이동·회전 시나리오로 측정하고, 허용 범위를 넘으면 고정을 풀고 재샘플링한다. 현재 프레임의 손 IK 목표는 이미 갱신된 외부 무기 월드 소켓을 다시 읽는 대신, 평가 중인 주손 Transform과 캐시한 무기·그립 로컬 Transform으로 계산해 순환 의존을 피한다.

Copy Pose 부위는 표시 메시 평가가 끝난 뒤 실행하도록 선행 관계를 설정한다. 원본→표시→부위 순서가 병렬 평가에서도 유지되는지 확인한다. 원본 커브가 실제 최종 몽타주 블렌드 값으로 전달되는지 관측하고, 후단 그립·접지 커브를 이름만 존재하는 것으로 검증하지 않는다.

## 손 그립

### 한손검

먼저 주손과 칼자루의 위치·회전을 캐릭터별 오프셋으로 정렬한다. 이어 손가락 체인과 기준 포즈를 점검하고, 리타게팅된 손가락에 필요한 범위만 보정 포즈를 적용한다. 손목·팔 전체를 손가락 보정 마스크에 포함하지 않는다.

손가락 체인의 본 수가 일치하면 FK 회전 전달의 `One to One`을 우선 검토한다. 손가락 본이 다르거나 누락된 캐릭터에는 매핑 검사를 하고 해당 체인만 제외한다. 이는 UE의 FK 체인 옵션을 적용하는 설계이며 모든 모델의 그립 품질이 자동으로 같아진다는 뜻은 아니다. [공식 Operation Stack](https://dev.epicgames.com/documentation/unreal-engine/retargeting-operation-stack-in-unreal-engine-5-8)

최종 가중치는 장착 상태, 동작 커브, 품질 설정을 곱해 구한다. 한손검 기본 그립은 장착 중 활성화하되 납도·손을 놓는 연출·사망 상태에서 부드럽게 해제한다. 커브가 없을 때는 명시한 장착 상태 기본값을 사용하고, 새 동작마다 임의의 태그 문자열을 추가하지 않는다.

장비 변경 시 Anchor 캐시를 무효화한다. 현재 원본 소켓만으로 캐시하는 경로를 확장할 경우 동일 소켓에 다른 무기가 연결되어도 이전 보정이 남지 않아야 한다. 기존 자동 Anchor와 타깃 Mesh Socket을 동시에 적용하지 않고, 명시 소켓/오프셋 프로필을 우선하고 기존 계산은 대체 경로로 둔다. Mesh Socket은 메시별 부착점을 제공한다. [공식 Socket 문서](https://dev.epicgames.com/documentation/unreal-engine/skeletal-mesh-sockets-in-unreal-engine)

### 양손 무기

양손 무기 도입 때 주손→무기→보조손 순서로 목표를 계산한다. 보조손에는 Two Bone IK, 팔꿈치에는 Joint Target을 사용한다. 과도한 팔 늘리기는 기본적으로 허용하지 않고 체형별 보조손 위치를 조정한다. 손목 IK와 손가락 포즈는 별도 단계다. [공식 Two Bone IK](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-two-bone-ik-in-unreal-engine)

주손에 부착된 무기 위치로 주손 자신을 다시 추적하는 루프를 만들지 않는다. 잡기·놓기 구간은 동작 커브로 제어한다. 현재 한손검 완료를 양손 무기 구현에 의존시키지 않는다.

## 발 고정과 지형 접지

### 리타게팅 미끄러짐

원본 자체의 미끄러짐, 실제 이동 속도와 보폭 불일치, 체형 변환 오차를 먼저 분리한다. 잘못된 이동 속도를 IK로 감추지 않는다. 게임플레이 이동 수치를 유지해야 하는 경우 표시 애니메이션의 보폭·재생 보정 범위를 별도로 판단한다.

원본 애니메이션에 MotionExtractorModifier로 발 속도 커브를 생성하고, 타깃 다리 체인에 IK Goal과 Solver를 구성한다. 임계값은 해당 애니메이션의 속도 곡선을 보고 정한다. 인플레이스 모션은 어떤 좌표계의 발 속도가 접지 구간을 표현하는지 먼저 검증하고, 맞지 않으면 명시적 접지 커브를 사용한다. [공식 Speed Planting 가이드](https://dev.epicgames.com/documentation/unreal-engine/fix-foot-sliding-with-ik-retargeter-in-unreal-engine?lang=en-US)

UE 5.8에서는 `Run IK Rig`와 하위 `Speed Plant IK Goals` 구성을 사용한다. Op 클래스와 Python 노출 여부는 설치된 5.8 엔진 API로 확인한 후 생성 도구에 반영한다. 문서의 UI 이름을 그대로 Python 클래스명이라고 가정하지 않는다. [공식 Operation Stack](https://dev.epicgames.com/documentation/unreal-engine/retargeting-operation-stack-in-unreal-engine-5-8)

### 지형 접지

리타게터의 정적 바닥 제약과 별개로 실제 월드 지형을 조회한다. 후단 접지는 발을 뻗을 수 있는 범위 안에서 높이·회전을 맞추고, 양발 오차를 고려해 골반을 제한적으로 이동시킨다. 발바닥 높이는 캐릭터별로 저장하고 발 회전은 지면 법선을 반영하되 최대 각도를 제한한다.

접지 상태는 해제, 추적, 고정으로 관리한다. 고정 시작 시 목표를 저장하고, 해제 임계값과 시간 보간을 두어 경계에서 반복 전환하지 않도록 한다. 다리 최대 도달 범위나 캐릭터 이동량 한계를 넘으면 고정을 풀어 다리 늘어남과 스냅을 막는다.

| 상황 | 접지 정책 |
|---|---|
| 대기·일반 이동 | 접지 커브와 지면 유효성을 따라 적용 |
| 공격 | 발별 지정 구간에만 적용; 이동 공격 전체를 강제로 고정하지 않음 |
| 회피·공중·사망 | 블렌드 아웃; 새 고정 목표 생성 중지 |
| Trace 실패·절벽·과도한 단차 | 도달 불가능한 목표 해제, 입력 포즈로 복귀 |
| 순간이동·외형 변경·리스폰 | 고정 위치와 보간 이력 초기화 |
| 움직이는 발판 | 지원 시 발판 로컬 목표로 저장; 미지원 시 고정 해제 |

Speed Planting과 월드 접지가 서로 다른 수평 목표를 동시에 고정하지 않도록 한다. 첫 구현에서는 리타게팅 단계의 미끄러짐 감소와 월드 높이·회전 보정을 먼저 결합한다. 추가 수평 고정은 미끄러짐 측정 후 필요한 동작에만 도입한다.

## 헤어와 의상 물리

| 부위 | 설계 선택 | 전제 |
|---|---|---|
| 작은 헤어 묶음·끈·장식 | AnimDynamics | 보조 본과 스킨 가중치 존재 |
| 신체 충돌이 필요한 긴 머리·체인 | RigidBody | 적절한 Physics Asset과 제약 구성 |
| 넓은 치마·망토·긴 코트 | Chaos Cloth 파일럿 | 시뮬레이션 메시, 고정 영역, 충돌 데이터 제작 |
| 단단한 Armor007 부위 | 기존 스키닝·Leader Pose | 유연한 부위를 별도로 식별 |

AnimDynamics는 평면·구형 제한으로 간단한 관통 방지를 구성한다. RigidBody는 Physics Asset 기반의 충돌이 필요한 보조 구조에 사용한다. 실제 품질·비용은 본 수와 제약에 따라 측정한다. [AnimDynamics](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-animdynamics-in-unreal-engine), [RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)

Leader Pose 자식에서 독립 본 물리를 수행한다고 가정하지 않는다. 독립 평가가 필요한 동일 계열 부위는 Copy Pose 후 보조 물리를 적용하고, 본 매칭·추가 본 초기 자세·계층을 검사한다. Skeleton 포인터 일치만으로 Leader Pose 적합성을 판단하지 않는다. 별도 헤어 리그는 Head 부착과 자체 AnimBP를 사용하며 서로 다른 스켈레톤을 무조건 Copy Pose로 연결하지 않는다. [공식 모듈러 캐릭터 문서](https://dev.epicgames.com/documentation/unreal-engine/working-with-modular-characters-in-unreal-engine)

Chaos Cloth는 독립 Cloth Asset과 컴포넌트를 이용하는 경로를 우선 조사한다. 렌더·시뮬레이션 메시, 가중치 전달, 고정 Weight Map, 충돌 Physics Asset을 준비한다. 별도 컴포넌트의 렌더 비용과 기존 의상 중복 렌더를 확인한다. 기존 SkeletalMesh 전용 툰 처리 경로에 자동 포함되지 않으므로 재질·Stencil 73·외곽선을 별도로 검증한다. [공식 Panel Cloth Editor](https://dev.epicgames.com/documentation/unreal-engine/panel-cloth-editor-overview)

표시 컴포넌트의 게임플레이 충돌을 켜는 것으로 천이나 보조 본의 자체 충돌 설정을 대신하지 않는다. 타격 판정에 불필요한 충돌·Overlap은 계속 제외한다. 히트스톱에는 보조 물리도 정지하거나 안정적으로 유지하는 정책을 적용하고, 재개 시 큰 시간 간격을 한 번에 적분하지 않는다. 전환·리스폰·순간이동·LOD 복귀 시 해당 솔버의 재설정 경로를 사용한다.

## 성능과 실패 처리

플레이어는 손 부착 정확도를 유지하고, 원거리 몬스터는 발 지형 보정과 보조 물리부터 줄인다. 품질 변경은 히스테리시스와 블렌드 시간을 두고, 비활성 기능의 Trace·솔버 실행도 중단한다. 단순히 출력 가중치만 0으로 만들고 모든 계산을 계속하는 방식은 피한다.

원본 메시 평가 축소는 별도 최적화 항목이다. 몽타주 Notify, GAS 시전, 공격 판정과 히트스톱 회귀 검사 없이 빈도를 줄이지 않는다. 소스·표시 이중 평가가 병목으로 확인되면 일반 P09의 오프라인 리타게팅과 애니메이션 공유 가능성을 다음 설계로 검토한다.

선택적 폴리싱 참조가 누락되면 해당 효과를 비활성화하고 기존 표시 포즈로 복귀한다. 필수 메시·리타게터 오류는 기존 외형 적용 거부 정책을 따른다. 외형 변경은 새 참조 검증과 준비 후 수행하고 실패 시 기존 표시·장비 연결을 유지한다. 저장 실패로 이전 선택을 유지하는 기존 동작도 보존한다.

Development 전용 관측 항목으로 그립 원점·목표, 발 Trace·고정점, 골반 보정량, 활성 품질 등급, 원본·표시 커브, 솔버 비용을 제공한다. 명령은 `pg.Appearance.*` 접두사를 제안하며 실제 구현 전에는 사용 가능한 명령으로 문서화하지 않는다.

## 검증과 수용 기준

### 자동 검사

기존 RunPlayableCharacters의 validate/runtime/automation 경로와 PGCharacterProbe를 확장한다. 기존 명령만 실행해 새 폴리싱 항목도 검사했다고 보고하지 않는다. 다음 항목의 실제 검사가 추가되어야 한다.

- 본·소켓·커브·포즈 스켈레톤 호환성, 유한 Transform, 중복 장비 키, 비정상 제한값, 품질 설정 범위.
- 설정 재생성·새 프로세스 재로드·백업 복구와 무관한 필드 보존.
- 각 캐릭터의 실제 GAS 공격에서 그립 오차, 접지 구간 이동량, 골반 변위, 본 길이 기록.
- P09 기존 체형 하한 검사와 다리 길이·스케일 검사. 머리–골반 약 41.2cm는 기존 보고서의 참고값이며 모든 포즈의 고정 정답으로 사용하지 않음.
- 반복 외형·장비 변경, 저장 실패, 공격 중 선택 차단, 미지 ID, 사망·리스폰·스테이지 전환.
- 폴리싱 전후 공격 횟수·피해·Notify·타격 시각과 VFX 기준점 회귀.

### 시각 검수

실제 쿼터뷰와 근접 디버그 카메라에서 연속 영상을 남긴다. 7종 플레이어는 대기·이동·기본 콤보·액티브·회피·피격을, P09 4종은 추격·공격·사망을 포함한다. 평지·경사·계단·급회전, 품질 경계 왕복, 외형 교체 직후도 검수한다. 정지 이미지와 본 이동량만으로 그립·접지 품질을 판정하지 않는다.

다음은 대표 에셋 파일럿에서 조정할 초기 수용 제안이다. 확정값과 제외 구간은 프로필 및 실행 보고서에 기록한다.

| 항목 | 초기 기준 제안 | 측정 방법 |
|---|---|---|
| 그립 정렬 | 지정 그립 구간의 접촉 기준점 오차 1cm 이내, 방향 오차 5도 이내 | 손목 자체가 아닌 저작한 손 접촉 좌표계와 무기 그립 기준 비교 |
| 발 미끄러짐 | 정지 바닥에서 한 접지 구간의 수평 이탈 2cm 이내 | 발바닥 기준점을 월드 또는 지지체 로컬 좌표로 추적 |
| 지형 침투 | 안정 접지 구간의 바닥 침투 1cm 이내 | 발바닥 표본점과 충돌면 비교, 회피·공중 제외 |
| 전환 품질 | 외형·LOD 복귀 후 비정상 튐·잔류 고정·지속 진동 없음 | 연속 캡처와 상태 이력 비교 |
| 전투 회귀 | 피해·공격 이벤트 수 일치, 논리 타이밍 변경 없음 | 동일 입력·시드의 기준 실행과 비교 |

오차 기준 통과와 별개로 엄지 뒤집힘, 칼자루 관통, 무릎 꺾임, 과도한 골반 흔들림은 시각 수용 실패로 처리한다. 실패를 숨기기 위해 허용치를 자동 확대하지 않는다.

### 패키지와 성능

목표 사양·해상도·목표 FPS·실제 최대 동시 몬스터 수를 측정 전에 기록한다. 미정이면 결과를 탐색 측정으로 표시하고 성능 수용 완료로 선언하지 않는다. 동일 기기·설정·시드에서 기본 외형, 폴리싱 전체 활성, 품질 축소를 비교한다. 1/25/50/100마리는 탐색 부하 예시이며 프로젝트의 확정 목표 수치가 아니다.

프레임 시간 p50/p95/p99, 게임·렌더 스레드, 애니메이션 평가, Trace·솔버 시간, 드로콜·메모리를 기록한다. 전체 프레임 예산과 폴리싱 추가 예산을 먼저 정한 뒤 통과 여부를 판정한다. 패키지의 소프트 참조 쿠킹과 재시작도 검사한다. Animation Insights는 포즈·커브·몽타주를 관측하고 비용 원인을 좁히는 데 사용하며, 계측 오버헤드가 적은 실행의 프레임 측정과 함께 비교한다. [공식 Animation Insights](https://dev.epicgames.com/documentation/unreal-engine/animation-insights-in-unreal-engine)

## 구현 전 확인할 항목

- 설치된 UE 5.8의 IK Op·Speed Planting Python API와 최종 몽타주 커브 전달 경로.
- P09 스케일 복원 앞뒤의 IK 목표 단위와 골반·다리 길이 보존.
- 각 캐릭터 손가락·발끝·헤어 본, 기존 Physics Asset·Cloth 데이터의 실제 유무.
- 무기·VFX·피해 판정이 참조하는 메시와 소켓, 장비 변경 이벤트의 현재 제공 범위.
- Copy Pose·별도 헤어·Cloth의 평가 시점, 툰 재질·외곽선 적용 방식.
- 목표 하드웨어·최대 전투 부하·폴리싱 성능 예산.

이 항목들은 일반 문서만으로 확정할 수 없는 프로젝트별 실험 대상이다. 각 단계 실행 보고서에 선택한 경로와 확인 근거를 기록한다.

## 완료 기록 원칙

후속 구현 보고서는 단계별 변경 코드·에셋·재생성 설정, 실행 명령, 로그·영상·프로파일 위치, 수용 기준의 통과·실패·미실행 상태를 기록한다. 빌드와 자동 검사 통과, 직접 플레이 수용, 패키지 성능 수용을 구분한다. 본 문서는 설계 완료 상태이며 어느 구현 단계도 완료로 표시하지 않는다.
