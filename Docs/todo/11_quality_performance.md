# 11. 성능 예산·회귀 검증·치트 도구

우선순위 P0(스모크)/P1(부하 게이트) / 상태 구현 반영·잔여 검증 있음 / 선행 01부터 점진 적용 / 규모 중

## 현재 근거

`Source/PGActor/Projectile/Pool`에 투사체 풀링이 있으며 `PGUI/Manager/PGDamageFloaterManager.cpp`에도 위젯 풀이 있다. 기존 풀링을 대체하기 전에 재사용 수명과 부하를 측정한다. `PGBTService_SelectSkill`의 전역 적 탐색과 전투 중 동기 에셋 로딩은 우선 측정 후보다. Source/Plugins 검색에서 IMPLEMENT_*AUTOMATION 매크로 기반 테스트는 발견하지 못했으며 다른 테스트 방식의 존재까지 부정하지 않는다.

## 검증 계획

- M0: 빌드→맵 진입→적 스폰→처치→보상→다음 단계→종료를 수동 스모크 체크로 고정한다.
- 핵심 자동화: 스테이지 수량/중복 사망, 한 번 보상 지급, 피해 경계값, 아이템 장착 원복, 저장 왕복, 잘못된 데이터 검출. 구현을 그대로 복제하는 테스트는 만들지 않는다.
- 개발 맵에 시드·적 수·투사체 수·드랍 수·플로터 발생량을 설정하는 재현 시나리오를 둔다. 기존 Cheat 도구를 확장한다.
- 부하 제안값은 적 100, 활성 투사체 200, 드랍 100, 초당 플로터 요청 100으로 시작한다. 이는 실측 한계나 확정 콘텐츠 수가 아니다. 목표 PC/해상도/품질 프리셋 확정 후 조정한다.
- 제안 목표는 60fps, 프레임 p95 16.7ms 이내다. Game/Render/GPU 시간, p99 지연, 스폰/GC 피크, 풀 고갈 횟수를 함께 기록한다.
- 20분 반복 부하와 구간 전환 20회에서 메모리·활성 객체·구독/타이머 수를 비교한다. 풀 최대치와 초과 시 생략/재사용 정책을 명시한다.

## 수용 기준

- Development 패키지에서 동일 시드/설정으로 재현하고 하드웨어·빌드·콘텐츠 버전이 결과에 남는다.
- 풀 반환 후 이동·충돌·Shooter·효과·타이머 상태가 재발사에 오염되지 않는다.
- 진행/저장에 영향을 주는 회귀는 자동 검출되고 실패 로그에서 원인을 찾을 수 있다.
- 확정된 성능 예산을 넘으면 프로파일 근거로 상위 병목부터 해결한다. 측정 없이 모든 액터 풀링이나 전면 Tick 제거를 추진하지 않는다.

Shipping에서는 개발 치트와 대량 로그가 활성화되지 않도록 확인한다. 후순위: 별도 대규모 CI 인프라; 로컬에서 재현되는 실행 절차부터 자동화한다.

## 2026-09-19 구현 반영

PG.Stage 및 PG.Combat 자동 테스트 5개, PGStageStatus/PGStartStage/PGCombatStats 치트, Editor/Game 빌드와 실제 데이터 교차 검증을 추가했다. GPU/CPU 부하·30/60/120fps·100마리 스트레스 결과는 아직 측정하지 않았다.

상세 변경·재현 절차·최종 검증 결과: [1·2단계 실행 보고서](Stage12_Implementation_Report.md). 위 현재 근거는 최초 분석 시점 기록이다.

## 3·4단계 추가 반영

자동 테스트를 8개로 확장했고 모두 통과했다. 실제 사망→맵 재시작 20회와 저장 실패 원복·저장 복원·장비/빌드 성장을 검증했다. 100마리 추가/드랍 100개 부하에서 소환 상한 우회와 플로터 활성 목록 누락을 수정했다. 프레임 p95는 135.78→68.68ms, UI 평균 비용은 23.62→1.22ms였다. 60fps 제안 기준에는 미달하며 20분 soak/고정 투사체·플로터 부하는 아직 검증하지 않았다. 하드웨어·측정 조건·한계와 재현 도구는 [3·4단계 실행 보고서](Stage34_Implementation_Report.md)에 기록했다.
