# Inori LOD 연속 화면 품질 검증

## 범위

2026-10-03~04. 기존 성능 후보 `/Game/Art/ToonTest/Advanced/Performance/SK_Inori_ToonLOD`를 검사했다. **영상·프레임 검사는 완료, 화면 품질은 잔여 문제 있음**으로 판정한다. Bokusei 카타나 라이브러리와는 별도다. 실제 전투 맵 채택, 장비 교체, GAS 피격/사망 표현 및 에디터 외 실행·패키지 성능 인증은 포함하지 않는다.

대기·달리기·공격·회피·피격·사망을 반복 재생한다. 기존 Inori 검증에 없던 회피만 `AS_ElfSelenaDodge_F_Anim`에서 기존 ElfSelena→Inori 설정으로 리타게팅해 `/Game/Art/ToonTest/Inori/Animation/Quality/PGToon_AS_ElfSelenaDodge_F_Anim`에 추가했다. 원본 메시·리타게터·회피 원본 해시를 보존했다. 이 클립은 화면 검사용이며 게임플레이 이동/판정에 연결하지 않았다.

## 촬영 조건과 증거의 의미

- UE 5.8 / DX12 SM6 / RTX 3060 Ti / 드라이버 581.29.
- 네이티브 1280×720 및 1920×1080, 16:9, ScreenPercentage 100, TSR(`r.AntiAliasingMethod=4`), VSM, ShadowQuality 3.
- 수평 FOV 50°, 내려다보는 각도 35°. 거리 표기는 카메라와 `(0,0,78cm)` 조준점 사이 거리다. 다른 FOV·메시 바운드·화면비에 그대로 적용할 고정 거리 값이 아니다.
- `comparison`: 좌→우 LOD0/1/2, 같은 모션·시각·광원. 카메라 거리 850cm. 서로 다른 화면 위치이므로 투시 시점의 차이가 있어 픽셀 단위 메시 오차 측정으로 사용하지 않는다.
- `close`: LOD1 단독, 거리 460cm. 각 모션 4초.
- `sweep`: 달리기/공격 각각 16초. 자동 LOD 상태로 300→2800→300cm 왕복한다. 고정 LOD 전환 흉내가 아니라 `get_predicted_lod_level()`을 프레임마다 기록한다.
- 일반 `Shot` 프레임을 사용한다. HighResShot의 별도 렌더 결과를 이어 붙이지 않는다. PNG 원본과 월드 시간·애니메이션 시각·머리/손 위치·LOD를 함께 보존한다.
- 시뮬레이션은 고정 30Hz다. PNG 읽기/저장 때문에 벽시계상 실행은 느리다. 인코딩된 30fps 영상의 재생 속도는 실제 게임 성능의 증거가 아니다.
- MP4는 H.264 CRF 16, yuv420p다. 미세 선의 최종 판단에는 무손실 PNG 원본을 함께 사용한다. 검사는 전체 프레임의 해상도·누락·시간 간격·LOD·본 움직임과 선택 프레임/연속 프레임 묶음의 육안 검토로 구분한다. 모든 프레임에 대한 사람의 실시간 재생 승인을 의미하지 않는다.

## 관찰과 재현 조건

| 항목 | 조건과 관찰 | 처리 |
|---|---|---|
| 고정된 발 앞 그림자 조각 | 기존 갤러리 액터를 제거하고 새 모션 액터를 배치한 PIE. 720p/1080p 근접 달리기 등에서 움직이지 않는 검은 조각이 남음 | 숨겨진 비교 액터/가림막을 제거해도 남고, 캐릭터 그림자를 꺼도 일부 잔존. VSM 캐시를 끄면 사라졌다. 준비 중 캐시 초기화 후 다시 켜는 방식으로는 재발했으므로 해결로 판정하지 않음 |
| 매우 얇은 정수리 머리카락 | 720p, 달리기, 거리 460/850cm. 머리 위 얇은 곡선이 점선처럼 보이거나 농도가 바뀜 | 같은 자세의 LOD0에서도 확인됨. LOD1 전용 형상 붕괴로 분류하지 않는다. 얼굴 SDF/헤어 방향 맵을 추가할 근거로 삼지 않음 |
| 자기 그림자의 작은 점무늬 | 근접 달리기의 허벅지/종아리 등 | 캐릭터 그림자를 끄면 감소. LOD0/1 및 캐시 비활성 비교에도 일부 존재. 그림자 샘플링/해상도 후속 폴리싱 대상으로 분리 |
| 반복 경계 | 피격·사망 클립의 끝→시작에서 자세가 즉시 복귀 | 반복 재생 장치의 리셋이다. LOD 팝이나 실제 사망 복구 동작으로 해석하지 않음 |

그림자 분리 실험은 `Saved/ToonTest/LODQuality/20261003T143020633708Z`와 `20261003T143559363944Z`에 있다. 후자는 baseline → 캐릭터 그림자 끔 → VSM 캐시 끔 → LOD0/캐시 끔 순서의 8초 영상과 240개 원본 프레임을 제공한다. 초기화 후 재발 확인 및 컴포넌트 설정 비교는 아래 실행 결과를 따른다. 전역 프로젝트 설정이나 상시 캐시 비활성 최적화를 적용한 것은 아니다.

최종 바운드 실험 `20261003T152343640709Z`는 **Auto/Bounds 1 → Always/Bounds 1 → Always/Bounds 1.5**의 순서다. 3초씩 총 270프레임에서 실제 달리기 본 움직임, 고정 LOD1, 캐시 켜짐을 확인했다. Always만으로는 잔상이 남고, Always+Bounds 1.5에서는 발 앞 조각이 사라졌다. 이는 바운드와 VSM 캐시 무효화 범위를 조사할 근거이며, 정확한 엔진 내부 원인 전체를 확정한 것은 아니다. Auto+Bounds 1.5는 검사하지 않았으므로 Always가 반드시 필요하다고 단정하지 않는다.

이 조합은 **수정 후보**로만 제시한다. 바운드 확대는 컬링·LOD 선택·그림자 비용에 영향을 줄 수 있다. 아래 거리 표는 Bounds 1에서의 결과이며, Bounds 1.5에서 동일 거리가 유지된다고 주장하지 않는다. 실제 전투 캐릭터의 바운드를 고친 뒤 전환 거리와 다수 개체 비용을 다시 검사해야 한다. 공용 메시/맵/머티리얼에 이 값을 저장하지 않았다.

바운드 실험의 첫 실행 `20261003T145308975385Z`는 렌더링 속성 변경이 애니메이션 인스턴스를 재생성해 Always 구간이 T 포즈가 됐다. `validation_rejected.json`에 거부 근거를 기록했으며 품질 근거로 사용하지 않는다. 모든 렌더 설정 변경 뒤 `animation_data`와 실제 재생을 복구한 최종 실행만 위 결론에 사용했다. 최종 짧은 실험은 별도 Bokusei NullRHI 가져오기와 동시 진행했고, 프로세스 명령을 확인해 그 가져오기만 허용했다. 성능 수치로 사용하지 않는다. 720p/1080p 본 촬영은 해당 가져오기 시작 전 완료됐다.

## 권장 LOD 설정

현재 샘플에서 얼굴·헤어·주 실루엣의 큰 LOD1 붕괴를 확인하지 못했다. 메시를 다시 줄이거나 전환을 더 앞당길 근거가 부족하므로 기존 후보 값을 유지한다. 아래는 이 아트 검증 범위의 권장값이며 전투 맵 출시 승인값이 아니다.

| 설정 | LOD0 | LOD1 | LOD2 |
|---|---:|---:|---:|
| Screen Size | 1.0 | 0.5 | 0.25 |
| Hysteresis | 0.02 | 0.02 | 0.02 |
| 원본 대비 삼각형 목표 비율 | 100% | 25% | 12.5% |
| 실제 저장 정점 수 | 102,860 | 30,137 | 16,759 |

생성 기준은 BaseLOD 0이며 삼각형 목표 비율과 정점 비율은 같은 값이 아니다. 얼굴/헤어를 더 공격적으로 축소하지 않는다. 현재 Morph Target Remap은 꺼져 있으므로 표정 모프의 LOD 품질까지 검증됐다고 해석해서는 안 된다.

- 자동 LOD 사용 시 컴포넌트 `ForcedLOD=0`. 고정 검사용 API 값 1/2/3은 각각 LOD0/1/2다. 기존 `L_PGToon_PerformanceMotionTest`의 강제 LOD1 설정은 그대로 보존한다.
- 외곽선 `WidthPixels=1.15`, Strength 1을 유지한다. 같은 픽셀 폭은 1080p에서 화면 비율상 더 가늘게 보인다. 동일 화면 비율의 두께를 목표로 하면 1080p 1.725px가 대응값이지만, 이번 검증에서는 이를 새 검증 완료 설정으로 제시하거나 저장하지 않는다.
- 얼굴 SDF와 헤어 방향 맵은 추가하지 않는다. 얇은 머리카락 선의 시간적 가독성은 별도 머리카락 형상/알파 및 그림자 폴리싱 항목이다.

## 실행 결과

초기 720p 실행은 `20261003T142240485256Z`다. 2,400장 중 첫 대기 구간 1번 프레임이 에디터 뷰포트 크기 1246×386으로 찍혔다. 원본을 보존하고 앞 2프레임을 명시적으로 제외한 영상 2,398프레임을 검증했다. 이를 프레임 누락 없는 최종 실행으로 표시하지 않는다. 다음 실행부터 촬영 전 워밍업 스크린샷과 프레임별 PNG IHDR 해상도 검사를 추가했다. 검사에 걸린 실패 실행 `20261003T143330340499Z`도 보존한다.

초기 자동 전환 기록은 달리기/공격 모두 원거리 이동 0→1 약 885.2cm, 1→2 약 1766.2cm, 접근 2→1 약 1554.1cm, 1→0 약 790.9cm다. 이 수치는 이산 30Hz 샘플에서 처음 관찰된 전환 거리이며 수학적으로 정확한 경계값은 아니다.

1080p 본 실행은 `20261003T143838826121Z`다. **2,400프레임 전부** 해상도·1/30초 간격·LOD·본 움직임 검사를 통과했다. 모든 촬영 프레임에서 VSM 캐시가 켜져 있음을 기록했다. 두 해상도의 달리기/공격 왕복에서 같은 전환 프레임과 거리를 확인했다. 양방향 경계 전후 프레임 및 6종 모션 샘플에서 얼굴·헤어·주 실루엣의 큰 형태 팝은 관찰하지 못했다. 가는 머리카락 선과 자기 그림자 샘플링 문제는 위 표대로 남긴다.

## 적용 및 남은 작업

원본 메시·LOD 후보·전투 데이터·게임 맵의 설정은 유지했다. 기존 LOD 후보와 DefaultEngine.ini의 실행 전후 SHA-256이 일치한다. LOD 기준/얼굴·헤어 축소율 유지 권장과 그림자 바운드 수정 후보를 구분한다. 얼굴 SDF/헤어 방향 맵을 추가하지 않았다.

다음 우선순위는 실제 캐릭터의 애니메이션 바운드와 그림자 잔상을 수정하고, 변경된 바운드에서 자동 LOD 거리·다수 캐릭터 비용을 다시 확인하는 것이다. 그 뒤 전투 맵 조명·피격/사망 상태·장비 교체 표현을 연결한다. 이번 아트 영상만으로 전투 맵 채택이나 에디터 외/Development 패키지 60fps를 승인하지 않는다.

## 재현

```powershell
$pythonExe = 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/ThirdParty/Python3/Win64/python.exe'
& $pythonExe Tools/Validation/RunToonLODQuality.py --height 720
& $pythonExe Tools/Validation/RunToonLODQuality.py --height 1080
& $pythonExe Tools/Validation/ReviewToonLODQuality.py Saved/ToonTest/LODQuality/<실행ID>
# 그림자 분리 실험
& $pythonExe Tools/Validation/RunToonLODQuality.py --shadow-check
& $pythonExe Tools/Validation/RunToonLODQuality.py --invalidation-check
```

외부 인코딩/이미지 검사는 프로젝트 로컬 `Saved/ToonTest/QualityTools`의 Pillow 12.3.0, NumPy 2.4.6, imageio-ffmpeg 0.6.0을 사용한다. `python -m pip install --target Saved/ToonTest/QualityTools pillow==12.3.0 numpy==2.4.6 imageio-ffmpeg==0.6.0`으로 준비할 수 있다. 다른 Unreal 실행이 있으면 기본적으로 중지하며 기존 에디터를 종료하지 않는다. `--wait-editor-seconds`는 종료 후 10초의 빈 구간을 기다리고, `--allow-pack-import`는 프로세스 명령이 정확히 확인된 ConfigureBokuseiPacks.py의 NullRHI 실행만 허용한다. 렌더링 테스트 맵은 메모리에서만 변경하고 저장하지 않는다.
