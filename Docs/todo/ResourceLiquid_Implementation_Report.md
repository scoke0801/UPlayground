# 체력·격분 액체 구슬

## 구현

- `SPGResourceOrb`에서 구슬별 UI MID를 한 번 생성하고 강한 참조로 보관한다. 체력·격분의 기존 Ratio를 Fill에 연결하며 금속 프레임과 유리 반사는 유지한다.
- `Tools/Art/CombatHUD/ResourceLiquid.ush`는 원형 마스크, 두 파장의 수면, 내부 흐름과 수면 반사를 계산한다. 수위는 지수 보간하고 자원 변화량에 비례한 흔들림은 감쇠한다. 빈 구슬은 액체가 없고 가득 찬 구슬은 내부 흐름만 보인다.
- `CreateResourceLiquid.py`로 `/Game/UI/Combat/M_PGResourceLiquid`를 생성한다. `PGUIStyleSettings.CombatOrbLiquid`가 교체 경로이며 `/Game/UI/Combat`을 쿠킹 대상에 포함했다.
- 머티리얼 인스턴스에서 `WaveAmplitude`(기본 0.035), `WaveSpeed`(1.0), `FlowStrength`(0.55)를 조절할 수 있다. `Fill`, `LiquidTime`, `Agitation`, `LiquidColor`, `Phase`는 위젯이 갱신한다.
- 머티리얼을 읽을 수 없는 경우 기존 정적 구슬로 표시한다. 매 프레임 MID나 텍스처를 생성하지 않는다.

## 재현

`python Tools/Art/CombatHUD/RunResourceLiquid.py`

Development 에디터 빌드 → 머티리얼 생성 → 기존 회복약/HUD 검사 → 실제 PIE 연속 캡처 순서다. 실행 중인 프로젝트 에디터가 있으면 먼저 저장하고 종료한다. 결과는 `Saved/CombatHUD/Liquid_*`와 회복약 검사의 별도 시간 디렉터리에 기록된다.

## 2026-10-09 최초 검증 이력

- 최종 머티리얼 생성·저장 및 새 프로세스 SM6 셰이더 컴파일 PASS (`Liquid_20261009T082617/material.log`, `shader.log`). 초기 출력 채널 연결 오류를 수정했고 모든 노드 연결의 반환값을 검사한다. 그래프 편집 중의 임시 오류와 완성본 검증을 구분하기 위해 생성은 NullRHI, 최종 재로드·컴파일은 실제 D3D12 렌더러에서 수행한다.
- 최초 빌드의 include 경로 오류를 수정했다. 실행 중인 Unreal Editor가 DLL을 잠가 링크가 차단되어 최종 적용·시각 검증은 대기 중이다.
- 수정 후 UE 5.8 Development `-NoLink` C++ 컴파일 PASS. DLL 링크·실행 완료를 의미하지 않는다.
- 기존 바이너리의 회복약 검사는 PASS이나 새 액체 UI의 검증 근거로 사용하지 않는다.
- 네 Python 스크립트 문법 검사와 `git diff --check` PASS. 실제 HUD 연속 캡처·픽셀 변화 검사는 새 DLL 링크 후 실행해야 한다.
- 패키지 실행 및 장시간 GPU 성능 측정은 수행하지 않았다.

## 후속 시각 폴리싱 · 구슬 내부 수치

- 사용자가 최초 액체 UI의 적용 화면을 확인한 뒤 추가 폴리싱을 요청했다. 강한 세포 형태의 내부 무늬를 저대비의 넓은 흐름으로 교체하고, 깊이 명암·투과광·수면 반사 띠·길쭉한 유리 하이라이트를 조정했다.
- 생명력/격분/분노 라벨을 제거하고 현재/최대 수치만 144px 구슬의 안쪽 하단에 배치했다. 격분 지속시간도 수치 문자열에서 제거했다. 82px 폭의 축소 전용 영역으로 큰 수치의 테두리 침범을 방지하고 숫자 뒤 명암과 그림자로 대비를 유지한다. 기존 전투 바 위치·크기는 유지한다.
- `Liquid_20261009T084437`: Development 전체 빌드·링크, 머티리얼 생성 및 새 프로세스 SM6 컴파일 PASS.
- `20261009T084644168304Z`: 기존 회복약/HUD 실행 검사 PASS. 실제 `healed.png`에서 내부 수치·라벨 제거·수면·레이아웃을 확인했다.
- `Liquid_20261009T085040`: 1600×900 PIE 캡처 5장·체력/격분 표시 확인 PASS. 안정된 수위의 연속 프레임에서 수면 영역 변화 픽셀 147/196/259개로 애니메이션을 확인했다(`animation.json`).
- 첫 프리뷰는 기존 한국어 엔진 시작 smoke test 오류로 프로세스 실패가 있었으며, 영어 시작 후 게임 UI만 한국어로 전환해 재실행했다. 재실행은 캡처·정상 종료까지 통과했으나 후처리 Python에 Pillow가 없어 중단되었다. 후처리를 Windows 기본 System.Drawing으로 교체하고 이미 캡처한 프레임을 별도 검사해 통과했다. 전체 러너를 수정 후 다시 처음부터 실행하지는 않았다.
