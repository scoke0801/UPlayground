# 14 전투 사이클 구현·검증 기록

기준: 2026-09-20, Unreal Engine 5.8.2. **C++와 신규 에셋 구현, 메모리 프리뷰 검증 완료 / 기존 에셋 연결 저장 및 최종 디스크 재검증 대기.**

## 적용 범위

- A: 네이티브 보상 카드의 등급 프레임, ImageGen 아이콘, 현재 GAS 스탯→보상 후 스탯, 호버, 0.08초 순차 등장, 0.22초 선택 확정 연출. 빈 풀·재시작도 같은 카드 사용. 기존 StagePresentation/토큰 검증/저장 지급 콜백 유지. UI 없는 SubmitChoice 경로 유지.
- B: 스킬 행의 TelegraphDuration/RecoveryDuration/TelegraphRadius/TelegraphMaterial/ElitePresentationMontage/SlamVFX. 예고 시 위치를 고정하고 같은 반경으로 지면 투영 중심 판정. 정예는 원본 스켈레톤을 복제한 BP_EliteWarden, 적/스킬 ID 14001. 별도 표현 몽타주의 노티파이를 제거하고 기존 신체·무기 판정도 패턴 중 억제한다. 사망/EndPlay/GAS 취소에서 타이머·Decal·이동 잠금 정리.
- C: TextRender를 화면 공간 WidgetComponent와 PGUILootLabel로 교체. 등급 프레임·아이콘·짧은 낙하 아크·등급별 높이의 빔·출현음. 아크 중에도 획득 가능하며 완료 후 액터 Tick 중지. 저장 성공 후 제거/근처 인벤토리 목록 경로 유지.
- D: Normal/Heavy/Critical VFX·SFX·셰이크·히트스톱 프리셋과 치명타 플로터 크기/색. 플레이어별 셰이크 요청 간격 제한. 한 액터의 활성 히트스톱은 연장하지 않는다. 생성된 셰이크는 single-instance이며 최대 지속 .16초, 프리셋 요청 간격 .18초.
- 구간 데이터: 1~3구간 각각 일반 적 4/5/6마리를 3/25/48초에 배치하고 정예 1마리를 70초에 배치. 90~120초 플레이 시간은 자연 플레이 밸런스 검증 대상이다.

## 신규 에셋과 도구

- `/Game/DataCenter/CombatCycle`: 이미지 1, 출현/타격음 6, 셰이크 3, Niagara 3, 예고/빔 머티리얼 2, 정예 BP 1, 표현 몽타주 1.
- `Tools/Art/CombatCycle/T_CombatReward.png`: ImageGen으로 생성한 원본. 같은 폴더의 WAV는 시드 고정 합성음 원본.
- `ConfigureCombatCycleAssets.py`: 최초 기존 에셋 백업 후 연결·스킬·정예·구간 데이터 적용. `-PGPrepareOnly`에서는 신규 에셋만 저장하고 기존 에셋 변경은 메모리에만 적용한다.
- `ValidateCombatCycleAssets.py`: 저장된 연결 데이터 교차 검사. 준비 모드 결과는 `AssetsPrepared.json`으로 구분한다.
- `PreviewCombatCycle.py`: 별도 PIE에서 메모리 준비 데이터로 3구간 카드 선택 검사.
- `PreviewCombatElite.py`: 별도 PIE에서 정예 예고 안/밖 판정 검사. 테스트 전용 배치 액터는 맵에 저장하지 않는다.
- 디버그: `PGFeedbackStatus`, `PGCombatCycleSmoke`(PGTestProfile 필요), `pg.Combat.EliteDebug 1`, 기존 `PGDropItem <ID> <Seed>`.

UE 5.8의 숫자 맵 JSON exporter는 `Stats: {Health: {Stats: 250}}` 형태를 출력하지만 importer에는 숫자 값이 필요했다. 구성 스크립트에서 모든 기존 스탯을 정규화하고 재입력 후 전 행 값 일치를 검사한다. 이 문제는 메모리 준비 프리뷰에서 발견·수정했으며 손실된 데이터를 원본에 저장하지 않았다.

## 현재 차단 사항

작업 시작 전부터 실행 중이던 프로젝트 UnrealEditor.exe(PID 39640)가 원본 DLL 및 `DA_PGCombatFeedback.uasset` 등을 사용 중이다. 일반 링크는 LNK1104, 에셋 저장은 Windows Error 32로 실패했다. 사용자 작업을 강제 종료하지 않았다.

**따라서 기존 8개 에셋의 새 연결은 디스크에 아직 적용되지 않았다.** 새 정예 BP와 표현 에셋이 존재하는 것만으로 현재 디스크 프로젝트의 전투 사이클이 완성된 것은 아니다. 편집 내용을 저장하고 기존 에디터를 종료한 후 아래 순서로 마무리해야 한다.

```powershell
$enginePath = 'C:/Program Files/Epic Games/UE_5.8'
$projectPath = "$PWD/UPlayground.uproject"
& "$enginePath/Engine/Build/BatchFiles/Build.bat" UPlaygroundEditor Win64 Development "-Project=$projectPath" -WaitMutex -NoHotReloadFromIDE
& "$enginePath/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" $projectPath -unattended -NullRHI -EnablePlugins=PythonScriptPlugin -run=pythonscript "-script=$PWD/Tools/Validation/PrepareAndValidateCombatCycle.py"
& "$enginePath/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" $projectPath /Game/Maps/StageDevMap -game -unattended -RenderOffscreen -PGTestProfile=Cycle14DiskFinal -benchmark -seconds=80 -fps=60 '-ExecCmds=PGCombatCycleSmoke'
```

최종 적용 시 `-PGPrepareOnly`를 넣지 않는다. 그 후 디스크 기반 3구간/체크포인트 재시작, 최소·최대 줌에서 예고와 드랍 식별, 오디오 실제 청취를 확인한다. 이번 프리뷰는 NoSound였으므로 SFX 연결과 파일 생성을 청취 검증으로 간주하지 않는다. 기존 성능 목표(p95 16.7ms), 자연 플레이 회피 난이도 및 장시간 밸런스 수용은 완료했다고 주장하지 않는다.

Content는 별도 저장소다. 신규 CombatCycle 에셋 및 최종 변경되는 기존 데이터 에셋을 소스와 함께 관리해야 한다. 커밋/푸시는 하지 않았다.
