# 05. 입력 반응성·캔슬·타격 피드백

우선순위 P1 / 상태 구현 반영·잔여 검증 있음 / 선행 03, 04 / 규모 중

## 현재 근거

`PGAbilitySystemComponent::OnAbilityInputPressed`는 즉시 TryActivateAbility를 호출한다. `PGPlayerSkillHandler`는 콤보와 마지막 사용 시간을 관리하고 ComboWindow Notify도 존재한다. 이것만으로 범용 입력 버퍼가 완성됐다고 볼 수 없다. `PGAbilityPlayerSkill::ActivateAbility`는 몽타주 로드 실패 시 EndAbilitySelf 뒤 return이 없어 이후 사용 기록 경로로 진행한다. `PGAbilityHitReact`는 이벤트 포인터를 선검증 없이 참조한다.

## 목표와 구현 범위

- 먼저 잘못된 이벤트·몽타주·타겟에서 즉시 안전 종료하고, 성공한 활성화만 비용/쿨다운/콤보를 확정한다.
- PGAbilitySystem에 최근 입력 1개와 만료 시각을 둔다. 초기 제안 버퍼 120ms를 데이터로 노출한다. 누르고 있기/한 번 누르기/토글은 별도 정책으로 둔다.
- 스킬별 선딜·활성·후딜과 회피/다음 공격 허용 구간을 데이터/Notify로 정의한다. 사망은 예약을 폐기하고 피격·장비 교체의 캔슬 규칙을 명시한다.
- 확정된 피해 결과에 VFX/SFX, 제한된 히트스톱, 카메라 셰이크, 플로터를 연결한다. 최초 범위는 일반 공격과 강타 1종이며 강도·시간·중첩 상한을 데이터화한다.
- 피드백 강도 감소/끄기 설정과 다수 타격 시 합성·억제를 제공한다. 애니메이션 정지로 타이머/입력 만료가 어긋나지 않도록 시간 기준을 통일한다.

## 수용 기준

- 버퍼 창 안 입력은 가능 시점에 정확히 1회 실행되고, 창 밖·사망 전 입력은 실행되지 않는다.
- 쿨다운 거절·몽타주 누락·타겟 소멸은 사용 처리와 비용 소모를 남기지 않는다.
- 30/60/120fps에서 콤보·회피 캔슬 정책이 동일하다.
- 한 프레임 다수 타격에서도 정지/셰이크가 무한 누적되지 않으며 공격자·피격자 표현이 구분된다.

디버그: 입력 수신/예약/활성 시각과 거절 이유, 캔슬 창 표시. 후순위: 모든 스킬별 전용 연출과 고급 카메라 연출.

## 2026-09-19 구현 반영

최근 입력 1개/120ms 버퍼, 홀드 해제·사망·UI 차단 시 폐기, 스킬별 공격/회피 캔슬 비율, 기존 ComboWindow 연계, 몽타주 실패 안전 종료, 확정 피해 기반 히트스톱과 VFX/SFX/셰이크 훅을 구현했다. 버퍼 자동 테스트가 통과했다. 전용 VFX/SFX/셰이크 에셋, 사용자 설정 메뉴, 30/60/120fps 조작감 검증은 남아 있다.
