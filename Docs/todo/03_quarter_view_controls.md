# 03. 쿼터뷰 카메라와 조작 기준

우선순위 P1 / 상태 구현 반영·잔여 검증 있음 / 선행 01 / 규모 중

## 현재 근거

`PGCharacterPlayer.cpp`의 생성자는 SpringArm 길이 400, 컨트롤러 Pitch/Yaw 상속을 설정한다. `Input_Look`은 자유 Yaw/Pitch 회전, `Input_Move`는 카메라 기준 이동과 이동 방향 회전을 수행한다. BP에서 실제 값을 바꾸었을 수 있으므로 현재 화면이 3인칭이라고 단정하지 않는다.

## 목표 경험과 최소 범위

기본 플레이를 고정 방향 쿼터뷰로 정한다. 첫 검증은 WASD 이동+마우스 지면 조준+회피로 진행한다. 클릭 이동과 패드 조작은 후속 확장으로 남긴다.

- PGActor의 카메라 설정을 데이터화한다: 기본 각도, 거리, 줌 범위, 추적 지연, 화면 가장자리 보정. BP 기존 값은 프리셋으로 이관한다.
- 이동 벡터와 공격 조준을 분리한다. 마우스 지면 Trace 실패·화면 밖·유효 타겟 없음에는 마지막 유효 방향/캐릭터 전방으로 일관되게 대체한다.
- UI 위 클릭은 공격/이동으로 전파하지 않는다. 보상창·일시정지·사망 시 입력 모드와 포커스 복원을 정의한다.
- 장애물에 캐릭터가 가려지는 구간을 테스트하고 필요 구간에 가림 처리와 캐릭터 식별 표시를 넣는다.

## 수용 기준

- 이동 중 다른 방향으로 공격 가능하며 회피 종료 후 카메라와 조준이 튀지 않는다.
- 16:9와 21:9, 최소/최대 줌에서 위험 범위와 플레이어가 식별된다.
- UI 클릭, 포커스 상실·복귀, 리스폰 후 의도하지 않은 공격이 발생하지 않는다.
- 에디터에서 각도·줌을 바꿔 코드 수정 없이 비교 가능하다.

디버그: 조준 Trace/최종 방향/입력 차단 이유 표시. 위험: 기존 몽타주 루트모션과 회전 정책 충돌. 05에서 캔슬 타이밍과 함께 검증한다. 카메라 흔들림 강도와 끄기 옵션도 후속 피드백에 연결한다.

## 2026-09-19 구현 반영

쿼터뷰 DataAsset, 고정 회전·줌·추적 지연, 카메라 기준 WASD, 마우스 지면 조준, UI/포커스/사망 입력 차단을 구현하고 BP_LocalPlayer에 프리셋을 연결했다. 화면 가장자리 보정과 장애물 가림 표현은 미구현이며 16:9/21:9 시각 검증은 남아 있다.
