### AI와 생명주기

- `FPGSkillSelectionTuning`: 기본 가중치에 선호 거리·좌우 방향·최근 사용 감쇠를 곱한다. 기본값은 기존 선택과 동일하다. 지정한 적만 3초 후 미실행 선택을 재검토하며 다른 유효 후보로 바뀔 때 FIFO 예약 위치를 보존한다.
- `EntranceMontage`, `EntranceSeconds`, `WakeDistance`, `DormantLocomotion`: 감지/피해로 한 번 각성하며 완료 전 직접 GAS 활성화도 거부한다. 등장 중 사망하면 몽타주를 중단한다. 타격 이벤트를 우회하는 GAS 직접 피해도 수면을 해제한다.
- 15204만 취약한 측면 이동을 사용한다. 실제 관측한 플레이어 시전 이후 0.3초 지연, 6초 재사용 제한, 공격을 한 번 완료해야 다음 회피 허용, 최대 180cm·0.45초 이동과 0.4초 회복이다. NavMesh·전체 경로·캡슐 통로를 검사하며 최대 두 후보만 요청한다. 공격/회복 중에는 시작하지 않고 무적을 부여하지 않는다.
- 검성 15401의 무조건 가드 최우선을 해제하고 관측 후 반응 지연·14초 반복 제한을 적용한다. 기존 최소 공격 횟수·GAS 회복 잠금은 유지한다.
- 그리핀은 저공 경로를 0.15초마다 최대 다섯 방향으로 검사한다. 바닥·높이 차·캡슐 장애물을 확인하고 안전 방향이 없으면 정지한다. 공중 전역 내비게이션이나 고공 이착륙 구현으로 간주하지 않는다.
- 리치는 기존 예산 경로로 용병 15201을 2체 소환하며 생존 상한 2·쿨다운 14초를 사용한다. 소환체 드랍 차단·부모 제거 시 정리를 재사용한다. 검증은 엔진 Owner/Instigator 대신 `GetLivingPatternSummons()`의 실제 추적 목록을 사용한다.

## 재현과 증거

원본 명세는 `Tools/Validation/Data/MotionExpansion.json`이다. UE 5.8 내장 Python에서 `RunMotionExpansion.py --step <inspect|audit|apply|validate|runtime|performance|promote>`를 실행한다. `runtime --render`는 접점 화면을 저장하고 `performance --render`는 현재 5/20/50마리 PIE CSV를 기록한다. `promote --evidence <runtime 실행 폴더>`는 종료 코드 0·신규 플레이어 시전·5개 자율 선택의 PASS를 요구한다.

적용마다 변경 예정 패키지 목록·백업·변경 전 테이블·원본 명세를 `Saved/QA/MotionExpansion_*`에 저장한다. 에디터 저장/검증 실패 시 해당 실행의 백업으로 복원한다. 이전 생성기로 플레이어/몬스터 데이터를 재생성했다면 이 확장도 다시 적용하고 검증해야 한다. 원본 생성 순서를 건너뛴 상태를 부분 성공으로 판정하지 않는다.

### 현재 성능 측정 — 60fps 수용 미통과

`Saved/QA/MotionExpansion_20261010T114148391900/performance.json`과 각 CSV에 현재 구현의 측정을 남겼다. RTX 3060 Ti, 드라이버 581.29, 1280×720 오프스크린 PIE에서 구간마다 5초 예열 후 10초를 수집했다. 초기 스테이지 5체는 숨김·AI 중단 상태로 남으므로 전체 월드 개체 수는 각각 10/25/55다. 아래 개체 수는 별도로 배치한 전투 집단을 뜻한다.

## 적용 범위

`PGRoleAIController`에 선택 진단을 추가했다. 기본값은 꺼짐이며 콘솔에서 다음 순서로 사용한다.

```text
pg.AI.DebugEnemyID 15601
pg.AI.DebugDecisions 1
```

`DebugEnemyID 0`은 모든 적, `DebugDecisions 0`은 출력 중지다. Output Log 또는 실행 로그에서 `PGCombatDecision`을 검색한다. 동일 개체·사유·SkillID는 1초에 한 번까지만 기록하므로 이벤트 총횟수 측정에는 사용하지 않는다. Pawn 이름으로 같은 EnemyID의 개체를 구분한다.

| 기록 | 의미 |
|---|---|
| missing_skill / invalid_pattern / weight_disabled | 데이터 누락·패턴 오류·선택 비활성 |
| phase_required / guard_attack_requirement / summon_limit | 페이즈·반격 전 공격 횟수·소환 상한 미충족 |
| cooldown / out_of_range / no_line_of_sight | 쿨다운·사거리·시야로 후보 탈락 |
| selected_guard_priority / selected_phase_sequence / selected_weighted | 보스 반격 우선·페이즈 순서·가중 선택 |
| selection_retained / pressure_wait | 기존 선택 유지·공격권 예약 거절 후 대기 |
| started / activation_failed | GAS 공격 시작 성공·활성화 실패 |
| pattern_locked / phase_transition / recovery_locked | 진행 중 공격·페이즈 전환·다음 행동 제한 |
| invalid_combatant / missing_combat_data | 유효한 전투 대상이나 적 데이터·핸들러 없음 |
| approach_request_failed / retreat_request_failed / position_request_failed | 추적·후퇴·재배치 요청의 즉시 실패 |
| flight_floor_missing | 저공 이동의 바닥 탐사 실패 |

후보 탈락은 기존 필터 순서에서 처음 만난 사유를 기록한다. `pressure_wait`는 Director의 예약 거절을 뜻하며 비용 상한·FIFO·시작 간격의 세부 원인을 분리하지 않는다. 이동 요청 승인 이후의 경로 중단은 이번 범위에 포함하지 않는다.

각 로그에 적/스킬 ID, 대기 스킬, 페이즈, 타겟까지 2D 거리, 공격 비용, 기본 몽타주·표현 몽타주·공격 프로필 경로를 함께 남긴다. 프로필 경로는 접점별 모션을 찾기 위한 연결 정보이며 실제 재생 성공 증거는 아니다. 진단 때문에 추가 에셋을 동기 로드하거나 난수를 소비하지 않는다. 선택 가중치·반격 우선순위·공격권 정책·전투 수치는 유지한다.
