# 14. 1사이클 전투 루프 완결

우선순위 P1 / 상태 구현·프리뷰 검증, 에셋 연결 저장 대기 / 선행 02, 04, 05, 06, 08 / 규모 중

## 현재 근거

코드 확인 기준(2026-09-20) 루프의 배관은 대부분 연결되어 있고, 플레이어가 체감하는 표현 계층이 비어 있다.

| 영역 | 상태 | 근거 |
|---|---|---|
| 쿼터뷰 조작·카메라 | 동작 | `PGQuarterViewData`, WASD + 지면 조준 |
| GAS 전투 수치 | 동작 | `PGAtrributeSet`, 방어상수 공식 + 치명타, `PGCombatTuningData` |
| 입력 버퍼·캔슬 | 동작 | 120ms 버퍼, 스킬별 공격/회피 캔슬 비율, ComboWindow Notify |
| 스테이지 진행 | 동작 | `PGStageManager` — 유한 배치 스폰, 중복 처치 방지, 토큰 기반 1회 보상 |
| 보상 선택 UI | 미완 | `PGUIWindowRewardSelect.cpp` 67줄, `PGUIRewardCard.cpp` 18줄 |
| 드랍 표현 | 프로토타입 | `PGLootDrop`이 `TextRenderComponent` 문자열 라벨 사용 |
| 저장·재시작 | 동작 | `PGProfileSubsystem` 이중 슬롯, 체크포인트 |
| 적 패턴·텔레그래프 | 미완 | 08 문서의 정예 패턴·예고 일치·전역 탐색 최적화 미완 |
| 타격 연출 에셋 | 훅만 존재 | 히트스톱/CameraShake/Niagara 슬롯은 있으나 에셋 미연결 |
| 성능 | 목표 미달 | 적 100 기준 p95 68.7ms (제안 기준 16.7ms) |

이 문서는 개별 시스템을 더 넓히지 않고, **이미 있는 시스템을 하나의 플레이 가능한 사이클로 닫는 것**을 범위로 한다.

## 1사이클 정의

90초~2분 길이의 한 구간을 1사이클로 본다.

```
입장 → 교전 3~4웨이브 → 정예 처치 → 드랍 획득 → 보상 카드 1택 → 다음 구간
          ↑                                                  │
          └──────────── 빌드가 조금 강해진 상태로 ────────────┘
```

| 단계 | 플레이어가 느껴야 할 것 | 목표 시간 |
|---|---|---|
| 입장 | 이번 구간의 구성이 읽힌다 | 3초 |
| 교전 | 타격이 손에 남는다 | 60~90초 |
| 정예 | 예고를 보고 회피했다는 성취 | 15~25초 |
| 드랍 | 떴다는 순간의 보상감 | 2초 |
| 보상 선택 | 다음 판이 달라진다 | 5~8초 |

## 목표와 최소 구현

### A. 보상 카드 UI 완성

- `PGUIRewardCard`에 등급 색 프레임, 아이콘, 수치 델타 표기(`공격 320 → 422`), 호버 강조를 구현한다.
- 카드 3장은 0.08초 간격 순차 등장, 선택 시 확정 연출을 둔다.
- 기존 `StagePresentation` 메시지와 토큰 검증·지급 경로는 그대로 사용하고 표현만 추가한다. UI가 없는 자동 테스트에서도 진행 로직이 동작해야 한다.
- 빈 풀의 다음 구간 버튼을 카드와 동일한 시각 레벨로 제공한다.

### B. 정예 1종과 텔레그래프 일치

- 예고 Decal 범위와 실제 판정 범위를 같은 데이터 행에서 생성한다.
- 패턴 구성: 예고 → 강타 → 경직. 경직 구간이 회피·반격 창이 된다.
- `PGSkillDataRow`에 `TelegraphDuration`, `RecoveryDuration`을 추가해 데이터로 조정한다.
- 시전 취소·사망·스테이지 전환에서 예고 표시를 강제 정리한다.

### C. 드랍 표현 교체

- `TextRenderComponent` 라벨을 등급 색과 아이콘이 있는 빌보드 위젯으로 교체한다.
- 낙하 아크, 등급별 빔/SFX를 추가한다. 희귀 등급은 획득 전에 소리로 먼저 인지되게 한다.
- 겹침 해소는 기존 인벤토리의 근처 드랍 목록 경로를 유지한다.

### D. 타격 피드백 에셋 연결

- 이미 연결된 히트스톱/CameraShake/Niagara 슬롯에 일반타·강타·치명타 3종 에셋을 채운다.
- 치명타는 플로터 크기·색·히트스톱 시간을 차등한다.
- 강도·시간·중첩 상한은 `PGCombatFeedbackData`에서 조정한다.

## 수용 기준

- 렌더링을 켠 상태로 3구간 연속 플레이에서 진행 멈춤이나 보상 대기 고착이 0회다.
- 정예 패턴을 처음 보는 상태에서 예고만으로 회피할 수 있다. 예고 범위와 실제 피격 범위가 일치한다.
- 보상 선택 전후의 실제 피해량 변화가 수치로 확인된다.
- 최소·최대 줌에서 위험 범위와 드랍 등급을 식별할 수 있다.
- 사망 후 체크포인트 재시작에서 장비·빌드·누적 클리어가 유지된다.
- 한 프레임 다수 타격에서 히트스톱·셰이크가 누적되지 않는다.

## 디버그 수단

- 보상: 후보 풀과 가중치, 선택 토큰, 지급 결과 로그.
- 정예: 예고 범위와 판정 범위 동시 시각화, 상태 전이 표시.
- 드랍: `PGDropItem <ID> <Seed>`로 등급별 표현 확인.
- 피드백: 히트스톱 누적 시간과 억제된 요청 수 표시.

## 우선순위

**지금**: A, B, C, D. 네 항목이 1사이클 체감을 닫는 최소치다.

**다음에 다듬을 것**
- 일반 근접·원거리 적의 역할 분리(현재 9종이 역할 구분 없이 혼재).
- AI의 `GetAllActorsOfClass` 전역 탐색 제거와 적 등록 목록 도입.
- Game thread 50ms 병목의 애니메이션·물리 분해 프로파일(11과 연계).
- 피드백 강도 설정 메뉴, 패드 지원과 재바인딩.

**보류**: 다중 페이즈 보스, 아이템 외형 교체, 대형 패시브 트리.

## 착수 순서 제안

A가 가장 명확히 비어 있고 사이클 체감을 즉시 올린다. B는 전투 루프 자체의 재미에 더 직접적이다. C·D는 A·B 작업 중 에셋이 준비되는 대로 병행한다.

## 2026-09-20 구현 진행

A~D 코드와 신규 표현 에셋을 구현했다. 자동 테스트 10개 통과, 메모리 준비 PIE에서 3구간 보상 진행 및 정예 안/밖 판정을 확인했다. 실행 중인 기존 에디터의 파일 잠금 때문에 원본 데이터 에셋 연결 저장과 디스크 기반 최종 수용 검증은 대기 중이다. [구현·검증 기록](CombatCycle_Implementation_Report.md)을 따른다.
