# 3D 액션 카메라 근접 디더링

2026-10-10 / UE 5.8.

## 적용 범위

- 3D 액션에서 현재 카메라가 따라가는 플레이어, 카메라 근처의 모든 `PGCharacterEnemy`, 각 캐릭터의 재귀 부착 장비를 대상으로 한다. 환경이나 카메라와 플레이어 사이 장애물 투명화는 포함하지 않는다.
- `PGCharacterPlayer.GetCameraBodyFade`는 최종 시점과 캡슐 중심축 사이 거리를 사용한다. 캡슐 반경 + `CameraBodyClearance`(45cm)에서 완전히 사라지며, 그 바깥 `CameraBodyFadeDistance`(기본 100cm) 구간에서 SmoothStep으로 연결한다. 벽 충돌로 줄어든 실제 카메라 거리에도 반응한다.
- `PGPlayerController.UpdateHiddenComponents`가 CPD 슬롯 7(`CameraFadeAmount`, 0=보임, 1=숨김)을 본체·부착 장비에 전달한다. 완전히 사라질 때만 기존 뷰별 숨김을 적용한다. 기존 즉시 숨김의 출구 히스테리시스 대신 연속 거리 페이드를 사용한다.
- 쿼터뷰·다른 ViewTarget·원거리·플레이어 교체·종료 및 장비 분리 시 CPD와 기존 CustomDepth 값을 복원한다. 페이드 중 화면 공간 외곽선은 꺼서 디더링 구멍마다 검은 선이 생기는 것을 방지한다. 외곽선은 원거리에서 복원된다.
- 툰 표면·반투명 오버레이·Hull 생성기에 엔진 `DitherTemporalAA`를 연결했다. 원래 알파/디졸브에 곱하고 그림자 패스에서는 카메라 페이드를 우회한다. 기본 CPD=0이므로 비교 맵과 다른 캐릭터는 그대로다.
- 현재 장착 검의 `MI_Sword-Dagger`는 일반 재질이므로 원본 마스터를 `M_PGCameraFadeSword`로 복제해 Masked 디더링을 추가하고 해당 MI의 부모만 연결했다. 원본 공용 마스터 및 MI의 텍스처·스칼라 값은 유지한다. 이 변경도 백업·재로드 검사에 포함한다.
- CPD는 컴포넌트 공용 데이터이므로 프로젝트의 단일 로컬 플레이어를 대상으로 한다. 분할 화면의 서로 다른 시점별 페이드는 별도 구현이 필요하다.

## 몬스터 확장

- 컨트롤러 입구에서 Action3D와 플레이어 ViewTarget을 확인한다. 플레이어가 멀리 있어도 몬스터별 캡슐 거리를 독립적으로 계산한다. 쿼터뷰에서는 전체 페이드를 복원하고 몬스터 검색을 수행하지 않는다.
- 사망 시 충돌 질의가 꺼지는 기존 동작을 고려해 충돌 Overlap에 의존하지 않는다. 월드의 해당 클래스에 대해 가벼운 캡슐 거리만 검사하며, 근접 대상에 한해서 메시·장비를 열거한다. 별도 몬스터 Tick은 추가하지 않았다.
- 툰 재질은 연속 디더링을 사용한다. CPD 미지원 일반 재질도 완전 숨김 거리에서는 뷰에서 제외하므로 내부가 화면을 덮는 것을 막는다. 일반 재질 전체를 툰으로 바꾸지는 않는다.
- 몬스터와 장비의 Camera Ignore는 유지한다. 몬스터가 지나갈 때 Spring Arm이 갑자기 플레이어 쪽으로 당겨지는 동작을 다시 만들지 않는다.
- 확장 검증: `Saved/QA/CameraFade/20261009T153000/report.json` **PASS**, 정상 종료. Development Editor 빌드·에셋 재로드·`PG.Camera.*` 3개 및 렌더 18조건을 통과했다. 자동 검사는 먼 플레이어와 독립된 몬스터 중간 페이드, 장비 동기화, 충돌 비활성 몸체의 완전 숨김, 쿼터뷰/다른 ViewTarget/원거리 복원을 추가한다.
- 렌더는 기존 플레이어 6조건 + 실제 `BP_15205` 무장 P09 몬스터 6조건 + `BP_15305` 골렘 6조건이다. 몬스터 중간 디더링, 몬스터/골렘 완전 숨김, 복원 PNG를 열어 확인했다. 일반 재질 골렘의 중간 디더링을 구현·수용했다고 주장하지 않는다. 검증용 액터/카메라 위치는 저장하지 않는다.

## 재현 및 보존

`python Tools/Validation/RunCameraFade.py`: 에디터 빌드 → 기존 툰/Hull 머티리얼 백업 및 그래프 연결 추가 → 별도 프로세스 재로드 → `PG.Camera.*` → 실제 PIE 거리별 렌더.

기존 셰이딩 그래프를 재생성하지 않고 최종 Opacity/OpacityMask 뒤에 페이드를 추가한다. `Content/Art`의 MI/SK 파일 해시를 검사하며 적용·재로드 실패 시 에디터 종료 후 백업을 복원한다. 별도 ExternalAssets 아래 장착 검 MI는 부모 변경 대상이므로 전용 백업과 부모 재로드 검사로 검증한다. 실행별 근거는 `Saved/QA/CameraFade/`에 보관한다.

## 플레이어 검 소실 수정

- 디더링 추가 시 원래 OpacityMask에 연결된 함수 노드만 가져오고 출력 핀 이름을 누락했다. 원본 함수 출력은 `Base Colour / Emissive / Opacity`인데 빈 출력 이름으로 재연결하면서 첫 번째 Base Colour가 마스크로 들어갔다. 어두운 검날이 마스크 임계값에 잘려 정상 거리에서도 사라졌다. `Saved/QA/SwordFade/inspect.json`에 원본/변환 그래프 조사 결과가 있다.
- 원래 검은 Opaque이므로 기존 OpacityMask 자체를 사용하지 않았다. 검 전용 Masked 변형은 카메라 디더링 이전 커버리지를 상수 1로 고정해 원래 불투명 표시를 유지한다. 이미 생성된 잘못된 그래프도 적용 도구에서 백업 후 교정한다.
- 공용 연결 함수는 원래 출력 이름을 인자로 받아 보존하도록 수정했다. 검의 커버리지 입력이 반드시 상수 1인지 저장/새 프로세스 재로드 검사에 추가했다.
- 이전 CPD 슬롯 연결 검사만으로 검날 표시까지 보장할 수 없었다. 플레이어 캡처를 검날이 드러나는 뒤쪽 사선 구도로 변경해 정상 거리와 복원 상태에서 직접 확인한다.
