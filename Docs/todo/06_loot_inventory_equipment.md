# 06. 드랍·인벤토리·장비 비교와 획득 루프

우선순위 P1 / 상태 구현 반영·잔여 폴리싱 있음 / 선행 02, 04 / 규모 대

## 현재 근거

`PGItemDataRow.h`는 Id만, `PGRewardItemDataRow.h`는 ItemId만 정의한다. 무기 액터와 장착 어빌리티는 존재하지만 이것이 소유 아이템·인벤토리·드랍의 완성을 의미하지 않는다. Source/Plugins의 텍스트 검색에서 Inventory/Loot 구현은 확인하지 못했다. BP 에셋을 먼저 조사하여 재사용 여부를 확정한다.

## 목표 경험

처치→바닥 드랍 식별→획득→현재 장비 비교→장착→전투 수치/행동 변화가 한 구간에서 이어진다. 보상 카드는 추가 보상으로 두고 장비 파밍을 대신하지 않는다.

## 최소 설계

- PGData: 정의 ID, 이름/아이콘, 장비 슬롯, 등급, 기본 옵션, 드랍 가중치/수량 범위. 런타임 아이템 인스턴스는 고유 ID와 확정된 옵션 값을 가진다.
- PGActor: 드랍/획득 액터와 인벤토리 소유 컴포넌트. 최초는 무기 1슬롯·장신구 1슬롯·고정 슬롯 목록형 가방으로 제한한다.
- PGAbilitySystem: 장비 GE 적용/해제 핸들 관리. 액터 무기와 소유 데이터 연결을 명확히 한다.
- PGUI: 등급 라벨, 근접 획득, 가방, 비교 툴팁, 빈 공간 부족 알림. 등급은 색과 문자/기호를 함께 사용한다. 단순 등급 필터와 겹친 라벨 정렬을 제공한다.
- 인벤토리가 수용한 뒤 드랍을 제거한다. 같은 드랍의 연속 클릭/범위 획득 경쟁은 고유 ID로 한 번만 처리한다. 장착 실패는 기존 장비를 유지한다.

## 수용 기준

- 적 사망 1회에 드랍 판정이 1회 발생하고, 가방이 가득 차면 아이템이 바닥에 남는다.
- 장착/교체/해제 후 GE와 UI가 일치하고 아이템이 복제되거나 사라지지 않는다.
- 비교 화면이 변경되는 주요 수치를 보여주며 테스트 장비를 바꿨을 때 실제 피해 변화와 맞는다.
- 같은 시드의 드랍 결과를 재현하고 확정된 아이템 옵션은 저장/로드 후 보존된다(09 연계).

디버그: 지정 ID/등급 생성, 가방 채우기, 드랍 시드·가중치 표시. 후순위: 격자 테트리스 가방, 제작·거래·복잡한 필터 언어. 신규 모듈은 처음부터 늘리지 않고 기존 책임 안에서 시작한다.

## 2026-09-19 구현

GUID/옵션 드랍, 24칸 가방, 무기/장신구 슬롯, 비교·장착·해제·버리기, 등급별 근처 드랍 목록을 연결했다. 가득 찬 가방/중복/저장 실패는 획득을 확정하지 않는다. 기본 아이콘·외형·획득 연출과 바닥 라벨의 투영 겹침 해소는 폴리싱 대상으로 구분한다. 테스트와 실행 결과는 [3·4단계 보고서](Stage34_Implementation_Report.md)를 따른다.
