# P09 무기·등급별 몬스터 배리에이션

2026-10-10. 기존 P09 검사·검투사·철갑기사 6종에 **창병·대검병·술사 18종**을 추가한다. Unreal Engine 5.8의 기존 GAS·역할 BT·외형 컴포넌트·스테이지 스폰을 재사용한다.

## 제작·연결 범위

| 무기 역할 | 일반 남녀 | 숙련 남녀 | 정예 남녀 | 전투 구분 |
|---|---|---|---|---|
| 창병 | 15701 / 15702 | 15703 / 15704 | 15705 / 15706 | 긴 창의 회전 창격·내려 베기·축력 창격 |
| 대검병 | 15707 / 15708 | 15709 / 15710 | 15711 / 15712 | 느린 횡베기·올려베기·좁은 내려찍기 |
| 술사 | 15713 / 15714 | 15715 / 15716 | 15717 / 15718 | 거리 유지 마력탄·연속 봉인 지대·근접 마력 폭발 |

각 쌍은 여성 / 남성 순서다. 일반·숙련·정예는 P09 Armor 003 / 007 / 012의 다섯 모듈을 사용하며, 기존 보정된 남녀 본체·머리카락·리타게팅을 유지한다. 공격력·체력·방어력·이동 속도와 장착 무기도 등급별로 구분한다. 일반은 공격 1개, 숙련은 2개, 정예는 3개를 사용한다.

- `/Game/DataCenter/P09Weapons/BP_<ID>`: 18개 몬스터 BP. `DA_<ID>`는 외형과 고정 무기 장착을 소유한다. 적·스탯·사망·스킬 행은 기존 공통 DT에 등록한다.
- 창·대검은 손잡이를 원점으로 하는 프로젝트 전용 메시를 각각 3종 제작했다. 일반의 강철, 숙련의 가드, 정예의 금속 장식으로 실루엣을 구분한다. 부착 메시의 충돌은 비활성이고 실제 판정은 GAS 패턴이 소유한다.
- 술사는 기존 P09 Staff 001 / 002 / 003을 사용한다. 원본 P09 메시·재질과 원본 애니메이션은 수정하지 않는다.
- 신규 스킬 15751~15759는 공통 예고·조준 확정·회복·쿨다운·공격권·취소 경로를 사용한다. 정예의 추가 공격도 무제한 연속 가드나 무적을 만들지 않는다. 숙련·정예는 기존 제한된 위치 조절을 사용한다.

## 모션 선정과 접점

기존 [Art 모션 목록](ArtAnimation_UsageCatalog.md), [모션 근거](../Design/MotionBasedSkills/MotionCatalog.md), [확장 기획](MotionExpansion_AI_Design.md)을 확인하고 정확한 원본 패키지가 후보 CSV에 존재하는지 검사했다. Bokusei 변환본을 직접 연결하지 않고 실제 전투 드라이버인 SkeletonEnemy 리그에 원본을 리타게팅했다. P09 외형은 기존 표시 리그 변환을 사용한다.

- Frank Spear / GreatSword의 대기·8방향 걷기·달리기 **34개 원본**을 두 방향 BlendSpace에 연결한다. 술사는 양손으로 장대를 운반하는 Spear 이동 세트를 공유하고 시전에는 별도 RPG 마법 모션을 사용한다.
- 공격 원본은 Frank Spear 2개, Grruzam M_Big_Sword 3개, RPG Magic 3개다. **공격 데이터는 9종, 공격 원본은 8개**다. 정예 창병의 축력 창격은 회전 창격과 모션을 공유하고 예고·회복·각도·피해를 다르게 한다.
- 총 **42개 고유 모션 원본, 43개 이동/공격 연결**이다. [신규 사용 manifest](assets/P09Weapons/motion-use-manifest.csv)는 소비 몬스터 ID, 원본→변환 시퀀스→몽타주와 검증 범위를 기록한다. 기존 Art 전체 후보와 Dark Knight 사용 목록은 유지한다.
- 원본 Notify를 파생 시퀀스·몽타주에서 제거해 중복 피해를 방지하고 루트는 제자리로 굽는다. 공격 슬롯은 `DefaultSlot`이다. RPG의 Hips/Left_Hand 본 명명은 기존 전용 IK Rig를 복제해 처리한다.
- 실제 P09에 무기를 장착한 상태에서 9개 후보를 각 19시각으로 고정해 171개 궤적을 기록했다. 창끝 방향을 수정하고 전방 타격에 부적합한 Spear Attack03은 채택을 철회했다. 최종 창 접점은 원본 비율 0.20 / 0.335 / 0.20, 대검은 0.175 / 0.225 / 0.30이다. 창 사거리는 280cm, 대검은 250cm로 조정했다. 원본 비율은 게임 내 예고 시간과 구분한다.

## 스폰·보상 연결

`DT_StageData`의 1~5구간에서 명시적인 **18개 스폰 자리**를 교체한다. 일반은 1~2구간, 숙련은 3구간, 정예는 4~5구간에 등장한다. 기존 몬스터 종류도 최소 한 번 이상 유지한다.

- 전체 16웨이브·적 104마리·강화 선택 7회, 스폰 간격과 그 외 스테이지 필드는 유지한다.
- 신규 정예 6종은 기존 정예의 확정 드랍 자리를 교체하므로 확정 드랍 총량도 유지한다. 일반·숙련은 기존 Chaser/Shooter 드랍 풀을 사용한다.
- 6구간의 Dark Knight 15601과 보스 보상은 유지한다.
- 절차 생성 던전은 같은 StageManager/DT를 사용하므로 새 로스터를 함께 사용한다. 별도의 중복 스폰 시스템이나 던전 전용 몬스터 데이터는 추가하지 않았다.
- `MonsterVariationRoster.compose`는 무기 로스터가 설치된 상태에서 기존 생성기를 재적용해도 신규 스폰을 유지한다. 플레이어 스킬 회귀 허용 목록과 공통 schema 8 검증, 확정 드랍 검증도 신규 명세와 연결했다.

## 재현

원본은 `Tools/Validation/Data/P09WeaponVariations.json`이며 수치·등급·그립·스폰 교체 위치를 여기서 조정한다. `AuthorP09WeaponSpec.py`는 최초 명세 생성용이므로 수동 튜닝 후에는 의도 없이 재실행하지 않는다.

1. Blender에서 `Tools/Art/P09Weapons/BuildWeapons.py`를 실행해 창·대검 FBX를 재생성한다.
2. UE 5.8 포함 Python으로 `Tools/Validation/RunP09WeaponVariations.py --step apply`를 실행한다. 원본 백업·허용 패키지 목록·변경 전 테이블을 기록하고 실패 시 해당 트랜잭션을 복원한다. 저장 뒤 새 프로세스에서 재로드한다.
3. `--step grips`는 외형 18개만 갱신한다. `--step validate`는 저장 상태를 검사한다.
4. `--step runtime --render`는 18개 장착/외형 전환, 36개 실제 공격, 9개 자율 선택을 검사한다. `--enemy 15705`처럼 개별 몬스터를 지정할 수 있다.
   자율 선택 검사는 직접 스킬 실행을 호출하지 않는다. 근접 마력 폭발 검사에서는 후퇴하는 술사를 추격하는 상황을 만들도록 플레이어 위치를 보정한다. 이는 직접 입력 플레이가 아닌 보조된 거리 조건 검사다.
5. `--step poses --render`는 포즈·무기 끝 궤적을 기록한다. `--step dungeon`은 3시드의 던전 완주·복구와 신규 ID를 직접 관측한다.
6. `RunQA.py --suite full --skip-build`와 `TestP09Weapons.py`, `TestQARunner.py`로 공통 회귀·스폰/드랍 계약을 검사한다. 이번 작업은 C++를 변경하지 않는다.

## 검증 기록

최종 근거는 [검증 요약 JSON](assets/P09Weapons/implementation-evidence.json)과 아래 `Saved/QA` 실행 폴더다. 최초 적용에서 발견한 UE Python 슬롯 접근·RPG 본 명명·정수 쿨다운·기존 스탯 JSON 입력 문제는 수정했으며 실패한 적용은 자동 복원했다. 스크린샷 생성과 프로세스 종료 성공은 별개로 판정한다.

| 검사 | 결과 | 실행 근거 (`Saved/QA/` 아래) |
|---|---|---|
| 최종 적용 및 새 프로세스 재로드 | PASS, 기존 관련 외 데이터 동일성 포함 | `P09Weapons_20261010T123641833395` |
| 렌더 전투·외형·AI | PASS, 18종 외형 교체/무기 정리·36공격 피해/모션/회복·9스킬 자율 선택, 108장 캡처 | `P09Weapons_20261010T124510613379` |
| 던전 | PASS, 3시드 16웨이브 완주·보상·복구, 신규 18종 실제 관측 | `P09Weapons_20261010T123811310906` |

| Python 회귀 계약 | PASS, P09 4개 + QA runner 11개 | `TestP09Weapons.py`, `TestQARunner.py` |

공통 QA는 기존 바이너리를 사용해 빌드를 생략했다. 경고에는 테스트 월드의 초기 무기 미설정·소멸 월드 문맥, GameplayCue 경로, UI 직렬화 및 스트리밍 설정 경고가 포함되며 무경고 결과로 간주하지 않는다. 원본 전체 후보와 보스 사용 CSV의 SHA-256은 이전 모션 확장 증거와 일치한다.

공격 검사는 실제 활성 몽타주와 시간 진행, 손 본 이동, 오른손 부착 오차 1cm 미만, 실제 피해와 회복 종료를 함께 확인했다. 정지한 표적만 사용한 첫 자율 검사에서는 술사가 후퇴해 근접 기술이 제외되었다. 최종 검사는 스킬 선택 규칙을 변경하지 않고 근접 추격 조건을 유지해 방어기의 자연 선택을 확인했다. 108장은 모든 공격의 대기/예고/타격 캡처 수이며, 모든 중간 프레임의 미술 수용을 의미하지 않는다.

## 남은 수용 범위

직접 조작에 의한 난이도·회피 공정성·연속 모션과 청취 검수, 패키지 장시간 전투와 50체 성능 수용은 별도다. 이전 모션 확장 기록의 50체 60fps 미달을 해결했다고 간주하지 않는다. 무기 장식·전용 공격 VFX/SFX의 추가 폴리싱과 양손의 모든 중간 프레임 접촉은 후속 미술 검수 대상으로 남긴다.
