# 캐릭터 단위 영구 성장 — 2026-10-14

## 저장 경계

사용자 결정에 따라 캐릭터 단위 영구 성장을 적용한다. 기존 선택 가능한 캐릭터의 `CharacterId`를 소유권 키로 사용한다. 같은 외형으로 여러 캐릭터를 만드는 별도 생성 화면은 추가하지 않는다.

| 캐릭터 영구 보존 | 던전마다 초기화 |
| --- | --- |
| 레벨·경험치·능력치 분배·잔여 포인트 | 보상 카드의 능력치·전투 효과·선택 횟수 |
| 확정 옵션·GUID를 포함한 장비·가방·창고 | 체크포인트·보상 토큰·구간별 보상 횟수 |
| 재료·제작법 해금·빌드·장착 스킬 | RunId·시드·획득 및 경험치 중복 방지 기록 |
| 누적 승리·클리어·최고 구간 | 종료·보조 플레이 표식 |

`BeginNewRun`은 캐릭터 성장을 초기화하지 않는다. 이전 저장 실패로 대기 중인 경험치는 새 던전 저장에 함께 확정하며, 실패 시 기존 메모리와 대기 경험치를 유지한다. 시작 장비는 `bCharacterInitialized`로 최초 한 번만 지급한다. 가방을 비우거나 장비를 분해해도 다시 지급하지 않는다.

보스 보상은 승리 결과 슬롯에 저장한 뒤 다음 던전 시작 트랜잭션에서 캐릭터 창고로 옮긴다. 가방이 가득 차도 보존되며 반복 시작으로 복제되지 않는다. 창고는 가방과 별개이며 이번 단계에는 별도 용량 제한을 두지 않는다.

## 캐릭터 전환과 UI

- 첫 구간의 전투 준비 또는 첫 전투 진입 전 탐색에서만 전환할 수 있다. 경험치·전리품·보상을 얻거나 전투가 시작되면 다음 던전까지 전환을 제한한다.
- 비활성 캐릭터의 영구 필드는 `OtherCharacters`에 보관한다. 기존 이름 없는 프로필은 현재 표시 중인 캐릭터에 귀속시켜 기존 진행을 보존한다. 외형 에셋이 없는 기존 기본 메시라면 최초로 명시적으로 선택한 캐릭터가 기존 진행을 인계받는다.
- 이미 배치된 PCG 보물의 지급 키가 무효화되지 않도록 전투 전 캐릭터 전환은 현재 던전의 RunId를 유지한다. 보상을 받은 뒤의 전환은 차단한다.
- 캐릭터 전환 성공 시 이전 캐릭터의 능력치·스킬·제작 편집 초안을 해제한다.
- 아이템 비교 화면의 `캐릭터 창고에 보관`과 `재료·창고`의 `가방으로 꺼내기`를 사용한다. 장착품은 해제 후 보관하며, 꺼낼 가방 공간이 없거나 저장에 실패하면 원래 위치에 남는다.

## 이관과 작업 보존

- 저장 버전은 8에서 9로 변경했다. 기존 교대 슬롯 이름과 파일 경로를 유지한다. `bRoguelikeRuns`는 기존 데이터와 유한 던전 진행의 호환 필드로 남기며 영구 성장을 끄는 옵션으로 사용하지 않는다.
- v1~v8 원본은 기존 `BackupLegacySlots`로 바이트 백업·재검증 후 이관한다. 활성 캐릭터의 기존 장비·재료·성장을 보존하고 이관된 캐릭터에는 시작 장비를 재지급하지 않는다.
- 비활성 캐릭터 및 창고의 알려지지 않은 장비 데이터도 저장 차단 대상으로 검사한다. 필요한 데이터가 없어도 캐릭터를 삭제하거나 빈 캐릭터로 교체하지 않는다.
- 구현 전 메인·Content의 변경/미추적/삭제 총 21,578개 항목, 파일 16,429,237,308바이트를 `Saved/Backups/Permanent_20261014_212222/work.zip`에 보존했다. `manifest.json`에는 원래 HEAD·상태·삭제 목록·파일 SHA-256이 있다. ZIP64 내부 파일을 다시 읽어 해시를 검증했다. 두 저장소 모두 등록된 LFS 추적 패턴은 없었다.
- 첫 파일별 백업은 Windows 긴 경로에서 실패했고 해당 부분 결과는 남겼다. 위 ZIP64 백업이 완료본이다. 백업은 같은 드라이브의 로컬 사본이며 원격 푸시 또는 저장소 커밋은 수행하지 않았다.
