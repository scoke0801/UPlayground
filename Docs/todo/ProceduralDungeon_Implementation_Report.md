# 절차 생성 던전 구현 기록

기준: [기획서](../Design/ProceduralDungeon_Design.md), Unreal Engine 5.8.2, 2026-10-10.

## P2 환경·탐험 통합 — 2026-10-10

분기 전리품, 제작 방 변형, 보스 문 연출, PCG 환경 배치, 발견형 미니맵 보완, 환경 가림 처리를 구현했다. 아래 P2 첫 단계와 P1/P0는 당시 이력이다. 체크포인트 복원·패키지 성능·사람의 직접 완주 수용은 P3이며 자동 텔레포트·자동 처치로 대체하지 않는다.

### 구현과 조정 지점

- **분기 보상:** 보물방마다 기존 정예 `Rogue.Warden`의 가중치를 복사한 별도 `DungeonTreasure` 풀로 장비 1개를 보장한다. 방 중심에서 벗어난 봉헌 그릇에 드랍을 배치하고 기존 획득 입력·라벨·가방 정책을 사용한다. 1~3개 선택 분기의 추가 예산이며 기본 적 104마리·16웨이브·필수 강화 7회에는 추가하지 않는다.
- **저장:** 보상 키는 `런 ID + DungeonTreasure + 콘텐츠 버전 + 방 ID`다. 기존 프로필 트랜잭션이 아이템과 `ClaimedLoot`를 함께 저장한 뒤 드랍을 없앤다. 저장 실패·가방 초과 때는 남겨 재시도하고, 종료된 런이나 다른 런 ID의 보상은 거절한다. 새 런의 장비 초기화·영구 해금 정책은 유지한다. 추첨은 독립 스트림 6을 사용한다.
- **제작 방:** `UPGDungeonRoomDefinition` 8개(입구, 일반 Court/Tombs/Cross/Sanctum 4종, 정예, 보물, 보스)를 제작했다. 공통 28m 방·네 방향 소켓 위에 다른 포장 모양과 폐허 구성을 조립한다. 메시·재질·조각 변환·허용 회전을 데이터로 노출하고 선택은 독립 스트림 5를 사용한다. 높은 조각이 중앙 전투 영역이나 출입구 십자 영역을 침범하면 생성을 실패 처리한다.
- **보스 문:** 불투명 블록을 금빛 봉인 장벽, 0.6초 승강, 짧은 봉인음으로 교체했다. 필수 목표 완료→개방, 보스 진입→봉쇄, 처치·실패→해제의 기존 권위를 유지한다. 충돌은 진행 상태에 즉시 맞추고 시각만 보간하며 NavMesh를 다시 빌드하지 않는다. 메시·재질·소리·전환 시간은 던전 정의에서 조절한다.
- **PCG:** 실제 UE PCG 플러그인과 `PCG_PGDungeonEnvironment` 그래프를 사용한다. UPlayground에만 PCG 의존성을 추가했다. `UPGDungeonScatterSettings` 노드가 방·통로·금지 영역을 사용해 메시별 포인트를 출력하고 생성기가 ISM 조립과 수명을 관리한다. PCG가 진행·보상을 소유하지 않는다.
- **준비 상태:** `Environment` 단계에서 그래프 완료 콜백과 출력 유효성을 확인한 뒤 정적 충돌·실제 캡슐 경로 검증으로 넘어간다. 고정 대기를 완료로 간주하지 않는다. 요청 ID·컴포넌트 동일성을 검사하고 누락 그래프·시간 초과·취소·재생성을 처리한다. 실행 컴포넌트·그래프 복사본은 저장·PIE 복제에서 제외한다. 에디터 미리보기 저장 후 중복 실행 컴포넌트가 생기는 문제를 찾아 이전 미리보기 정리도 추가했다.
- **장식 제약:** 이번 PCG 장식은 비충돌이다. 식생은 실제 메시 반경까지 포함해 방·통로 확장 영역 밖에, 작은 잔해는 전투 공간 밖 모서리에 둔다. 장식 밀도는 구조·방 선택·전투·보상 난수와 독립적이다. 충돌 지형은 기존 바닥·경계벽과 보스 문이다.
- **환경 가림:** 던전 사본 재질의 인스턴스 사용자 데이터 2번을 사용한다. 카메라와 플레이어·근처 바닥 사이의 경계벽·장식을 약 0.18초에 걸쳐 디더링하고 가림이 사라지면 복원한다. 원래 식생 알파와 그림자를 보존하며 충돌·NavMesh를 바꾸지 않는다. 쿼터뷰·3D 액션에 적용하고 액션 카메라 지형 충돌은 유지한다.
- **미니맵:** 발견한 보물·획득 상태, 카메라 방향, 한국어 범례를 추가했다. 미발견 방 정보는 계속 숨긴다. 상시 개발용 목표 화살표·원은 제거하고 `pg.Dungeon.Debug`를 유지한다. 실제 720p에서 작았던 범례를 두 줄로 키우고 280×230 공간을 확보했다. HUD 안내도 제거된 개발 화살표 대신 길 탐험을 안내한다.

### 재현과 검증

- 실행: `Tools/PlayProceduralDungeon.ps1 -Seed 101026`. `-Preview`는 보상·전투 없는 탐험이다. 새 런 정책을 유지한다.
- 제작·검증: `python Tools/Validation/RunDungeonExploration.py --step <단계>`. 단계는 `build`, `assets`, `automation`, `runtime`, `paths`, `combat`, `p2`, `p2render`다.
- 에셋 제작: `Tools/Art/ProceduralDungeon/ConfigureDungeonP2.py`. 기존 던전·진행 데이터·맵을 백업하고 던전 사본만 수정한다. 원본 외부 아트와 고정 테스트 맵은 보존한다. 에디터 미리보기도 PCG 완료 후 저장한다.
- 근거: `Saved/QA/ProceduralDungeon/P2`의 단계별 `*.result.json`, 로그, `assets.json`, `Automation/index.json`, `paths/runtime.json`, `combat/runtime.json`, `p2/probe.json`, `p2render/probe.json`. P1 결과는 덮어쓰지 않는다.
- PG 자동 테스트 **60개 통과**(성공 49, 경고 포함 성공 11, 실패 0). 기존 전리품 트랜잭션 테스트에 보물방 결정적 ID, 저장 실패 후 재시도, 버리기·디스크 재로드 후 중복 지급 방지를 추가했다.
- 실제 월드 **100시드 경로 검사 통과**, 전부 첫 시도 성공·기본 배치 사용 0건. 방 키트 수·PCG 출력과 재생성 후 제한된 컴포넌트 수를 확인했다. 강제 실패·취소 후 복구도 통과했다.
- **3시드 전투 완주 및 7종 복구 검사 통과.** 시드 `101026`, `17`, `-2147483648`에서 기존 적 **104마리·16웨이브·강화 7회**를 유지했다. 자동 처치가 적용된 진행 검사다.
- P2 통합 검사에서 시드 101026의 제작 방 11개·PCG 포인트 140개·보물 2개를 확인했다. 장식 밀도를 낮추면 포인트만 96개로 줄며 레이아웃·모듈·보상 추첨은 동일했다. 보물 저장 실패·가방 초과 후 재시도·중복 획득 차단과 그래프 누락·생성 중 취소·지연 콜백 차단·복구를 확인했다.
- 가림 인스턴스 수는 쿼터뷰 3개·액션 2개였고 중앙 복귀 후 0개로 복원됐다. 전후 충돌 설정은 동일하고 액션 카메라 지형 충돌도 유지했다. 봉인→목표 완료 후 개방→보스전 재봉쇄→처치 후 해제를 실제 렌더에서 확인했다.
- 렌더 검수 중 보물 받침이 액션 시점에서 캐릭터를 가리는 것을 발견해 최대 크기를 140cm에서 95cm로 낮췄다. 검증 도구는 사용자 디스플레이 설정을 저장하지 않고 PIE 뷰포트만 변경하며 PNG 실제 픽셀 크기를 검사한다.
- 실제 전투의 `M_EliteTelegraph` 재질을 벽 근처에 표시해 쿼터뷰·액션 시점의 바닥 예고 대비와 가림을 확인했다. 이는 정적 시각 검증용 데칼이며 실제 공격 타이밍·회피 조작 검증으로 계산하지 않는다. 검증 실행은 `-nosound`여서 봉인음 연결은 구현했지만 청취 검수는 수행하지 않았다.
- **최종 결과: P2 구현 및 자동·렌더 검증 PASS.** Development Editor/UHT 빌드, 에셋 제작, 자동 테스트, 발견 상태 회귀, 100시드 경로, 3시드 전투, P2 통합 렌더의 최종 프로세스 종료 코드는 모두 0이다. 최종 렌더 11장의 실제 크기는 1280×720 및 1920×1080이며 입구·전리품·획득·두 카메라의 벽과 예고·보스 문 흐름·해상도별 미니맵을 확인했다. 그래프 누락 시 에디터 미리보기도 실패 상태로 전환하고 잔존 조립물을 정리한다.
- **종료 안정성 이력:** 작업 중 초기 실패 렌더의 종료에서 기존 `0xC0000005`가 다시 관찰됐다. 이후 최종 전투 렌더는 정상 종료했지만 해당 접근 위반의 원인을 확정·해결했다고 주장하지 않는다. P1 당시 FAIL 근거를 보존하며 전체 던전 수용 완료는 P3 검증까지 보류한다. 검증 스크립트는 종료 코드와 성공 표식뿐 아니라 Python 오류·ensure·치명적 오류·재질 컴파일 실패·보물 트랜잭션 실패도 검사한다.

### 후속 범위

P3: 생성/콘텐츠 버전과 확정 레이아웃 저장, 체크포인트 복원, Development 패키지 성능, 10개 시드 직접 완주와 20분 연속 플레이. 제작 방은 동일 소켓·단층 규격의 첫 키트이며 최종 아트 디테일·전투 리듬·샛길 보상 체감은 사람의 플레이 수용에서 조정한다. 충돌 PCG 장식·자유형 방·다층·스트리밍은 이번 P2 범위가 아니다.

## P2 첫 단계 — 발견형 미니맵 (2026-10-10)

P1 다음 작업으로 탐험에 필요한 발견형 미니맵을 추가했다. P2 전체 완료를 의미하지 않으며, 아래 P1/P0 검증 기록은 당시 근거로 보존한다.

### 구현 범위

- 좌측 상단에 방문한 방의 윤곽, 확인한 연결, 입구·발견한 현재 목표·보스, 청록색 플레이어 위치를 표시한다. 지도는 월드 축 고정이며 카메라 회전에 따라 회전하지 않는다.
- 방 내부에 들어와야 발견한다. 통로 이동이나 바닥 아래 추락은 다음 방을 발견 처리하지 않는다. 방문한 방의 미탐험 출입구는 짧은 선으로 표시하지만 목적지의 방 위치·역할·보상은 전달하지 않는다. 연결 전체는 양쪽 방을 방문한 뒤 표시한다.
- `PGActor/Dungeon/PGDungeonDiscoverySubsystem`이 현재 월드의 발견 상태와 UI용 제한된 스냅샷을 소유한다. UPlayground 생성기는 플레이 준비 완료 후 레이아웃을 초기화하고 플레이어 위치·현재 목표를 전달한다. PGUI는 생성기 모듈을 역참조하지 않는다.
- 발견·현재 방·목표 변경 이벤트로 지도 스냅샷과 표시 범위를 갱신한다. 플레이어 마커만 매 렌더에서 현재 위치를 반영하며 매 프레임 전체 지도 데이터를 재생성하지 않는다.
- 취소·재생성·실패·맵 종료 시 발견 상태를 지운다. 동일 시드 새 런에서도 이전 발견 정보가 남지 않는다. 고정 맵에서는 미니맵을 숨기며 전투와 `-Preview` 모두에서 작동한다.
- 미구현 분기 보상을 보장하는 상자 아이콘은 표시하지 않는다. 발견 정보의 영구 저장·체크포인트 복원은 P3 범위다. 기존 개발용 목표 화살표와 보스 문 동작은 유지한다.

### 재현과 검증

`python Tools/Validation/RunDungeonExploration.py --step <build|automation|runtime|render>`로 각 검사를 실행한다. 결과는 `Saved/QA/ProceduralDungeon/P2`에 분리하며 P1 근거를 덮어쓰지 않는다. 실행은 기존 `Tools/PlayProceduralDungeon.ps1 -Seed 101026`을 사용한다.

- UE 5.8 Development Editor/UHT 빌드 통과. 기존 deprecated API 경고는 남는다.
- PG 자동 테스트 60개 통과(성공 49, 경고 포함 성공 11, 실패 0). 신규 `PG.Dungeon.Discovery`는 미발견 정보 제한, 출입구 표시, 중복 방문, 음수 좌표, 추락, 목표 변경, 초기화와 잘못된 규격을 검사한다.
- 실제 PIE 탐험에서 시드 101026의 11개 방 발견·연결 확인·입구 재방문을 통과했다. 시드 17 재생성 및 취소 후 -2147483648 재생성에서 입구만 발견된 상태로 복구했다. 프로세스 종료 코드 0.
- 실제 렌더의 입구·전체 발견·재방문 화면 3장을 확인했다(`01_entrance.png`, `02_discovered.png`, `03_revisited.png`). 최초 화면에서 작고 마커와 겹친 방 이름을 발견해 지도·글자를 키우고 이름을 방 윤곽 위로 옮겼다. 수정 후 빌드·렌더 검사를 통과했고 최종 렌더 프로세스도 종료 코드 0이다. `render.result.json` 및 `render.probe.json`은 PASS다.
- 이번 P2 첫 단계의 빌드·자동 검사·실제 월드·렌더 검증은 PASS다. P1의 `0xC0000005` 원인을 수정하거나 기존 실패를 대체한 것은 아니다. 이번 탐험 모드 렌더에서는 재현되지 않았으며 P1 전투 렌더·전체 던전 수용의 기존 FAIL 기록은 유지한다. 자동 텔레포트는 발견 로직 검증이며 직접 조작 수용을 대체하지 않는다.

### 남은 범위

분기 전리품의 저장 트랜잭션, 제작 방 변형·보스 문 연출, PCG, 환경 가림 처리는 다음 P2 작업이다. 미니맵의 카메라 방향 표식·범례·해상도별 폴리싱과 두 카메라 직접 조작 검수도 남는다. P3 저장 복원·패키지 성능·직접 완주 수용은 아직 수행하지 않았다.

## P1 전투 통합 — 2026-10-10

P0 이후 필수 목표 5개와 보스의 플레이 가능한 전투 흐름을 연결했다. 아래 P0 기록은 당시 결과이며, 현재 실행기는 전투 모드를 기본으로 사용한다. 직접 전투 수용이나 P3 저장 복원 완료를 의미하지 않는다.

### 실행과 런 정책

## 구조와 책임

PGShared의 FPGDungeonLayout은 생성 버전·시드·시도·기본 배치 여부·안정적인 방 ID와 연결을 담는다. PGData의 UPGDungeonDefinition은 공간 규격과 테마 참조를 소유하며, 레이아웃 생성·검증은 PGDungeonLayoutBuilder가 담당한다. UPlayground의 APGDungeonGenerator는 월드 조립·정리·이동 검증·준비 상태를 담당한다. 새 모듈 역참조나 PCG 의존성은 추가하지 않았다.

주 경로는 입구 + 필수 목표 1~5 + 보스의 7개 방이다. 필수 목표 4는 정예 역할이며, 1~3개 분기를 깊이 1~2로 추가해 총 8~12개 방을 만든다. 분기 끝에는 보물 역할을 표시한다. 역할과 목표 ID만 생성하며 적·상자·보상은 아직 생성하지 않는다. P0에서는 순환 연결 0개를 사용한다.

방은 28m 정사각형, 통로는 길이 10m·폭 8m, 낮은 경계벽은 높이 1.8m다. 네 방향 중앙 소켓을 가진 공통 블록 규격이며, 제작 방 4종·보스 전용 모듈 등은 후속 작업이다. 메인 경로는 두 양의 격자 방향으로 진행하고 분기는 네 방향을 검사한다. 후보 열거와 분기 수에 상한이 있어 무제한 탐색하지 않는다.

구조·실내 장식·외곽 식생 난수를 분리하고 에셋 경로로 후보를 정렬한다. 장식 수 변경은 구조에 영향을 주지 않는다. 전투·보상 난수는 해당 통합 단계에서 기존 런 정책에 연결해야 한다.

## 준비와 복구

생성 요청마다 이전 타이머를 취소하고 요청 ID를 갱신한다. 소유 인스턴스 컴포넌트만 제거하고 새 바닥·벽·비충돌 소품을 조립한다. 에디터 미리보기는 동일한 시드 알고리즘을 사용하지만 플레이 가능 상태를 발표하지 않는다.

게임에서는 플레이어 이동·공격 입력을 중단한 뒤 내비게이션 잠금·대기 중인 더티 영역·빌드 완료 상태를 확인한다. 연결된 방 중심 사이의 완전 경로를 검사하고, 반환된 각 경로 구간을 실제 플레이어 캡슐로 스윕한다. 구조 연결성과 모든 연결의 통과 가능성을 함께 검사해 입구에서 모든 방으로 이어지는 경유 경로를 보장한다. 부분 경로·캡슐 충돌·입구 스폰 실패를 성공으로 처리하지 않는다. 입구 배치가 성공한 뒤 조작을 복원한다.

기존 NavMesh 반경은 35cm, 실제 플레이어 캡슐은 42cm다. 전역 설정은 보존하며, 작은 에이전트가 중간 방 모서리를 짧게 도는 경로 대신 방 중심을 경유하는 경로를 실제 캡슐로 검사한다. 향후 방별 AI 통합에서는 각 몬스터의 이동 에이전트와 추적 경로를 별도로 검증해야 한다.

정상 생성은 최대 3회, 그 뒤 고정 직선 기본 배치를 동일 기준으로 검증한다. 기본 배치도 실패하면 Failed 상태를 유지한다. 잘못된 테마 참조는 재시도로 해결되지 않으므로 즉시 실패한다. 취소·실패 중에는 플레이어를 정지 상태로 유지하며 새 생성 요청이나 맵 종료로 복구한다. 로딩 안내는 P0 개발용 한국어 화면 메시지다. 정식 로딩/오류 UI와 재시도 버튼은 후속 범위다.

기본 배치는 구조 검사 대상이며, 모든 방 규격과 엔진 설정에서 사전 인증된 완성 배치라는 의미는 아니다. 플레이 준비 전에 실제 월드 검증을 항상 수행한다.

## 아트 출처와 스타일

사용자가 지정한 폴더의 실제 이름은 `Content/ExternalAssets/LevelDesign`이다.

- RuinedCrypt: 폐성소 기둥·묘비·부서진 벽과 원본 재질.
- Dungeon_Pack 및 기존 폐성소 재질: 석재 포장·흙·이끼의 바닥 표현.
- 기존 Environment/ForestRuins의 나무 2종: 현재 테스트 맵의 숲 스타일 재사용.
- 기존 테스트 맵의 주광원·보조광·노출·안개·후처리를 복제한다. 두 방향광의 우선순위 충돌만 새 맵에서 정리한다.

외부 원본은 읽기 전용으로 사용한다. 인스턴스 렌더링이 필요한 메시·재질·부모 재질은 Dungeons/ForestSanctuary에 복제하고 usage 설정을 저장한다. 방마다 기존 석재 광장 마스크를 재중심화하고 텍스처의 월드 크기는 유지한다. 외곽 지면·식생은 비충돌이며 방·통로 확장 경계 밖에 배치한다. 플레이 가능한 바닥·벽만 내비게이션을 변경한다.

현재는 아트 스타일을 적용한 공간 검증용 블록이다. 방별 연출, 부서진 담장 실루엣, 다양한 지형·소품 밀도, PCG 그래프, 전면 가림 처리를 완성한 환경은 아니다.

## 개발 명령

- `pg.Dungeon.Generate <Seed>`: 게임 월드에서 새 시드 생성.
- `pg.Dungeon.Debug`: 15초간 방과 연결·목표 ID 표시.
- `pg.Dungeon.Validate`: 현재 구조와 실제 캐릭터 경로 재검사.
- `pg.Dungeon.Batch <Count>`: 1~10,000개 구조 시드 검사. 실제 월드 내비게이션 검사가 아니다.

## 검증 및 남은 수용 기준

최종 실행 결과는 Saved/QA/ProceduralDungeon의 result.json, runtime.json, render.json, Automation/index.json, ubt.log로 확인한다. 자동 검사는 직접 플레이를 대신하지 않는다.

- UE 5.8.2 Development Editor C++/UHT 빌드 성공. 기존 엔진 deprecated API와 권장 컴파일러 버전 경고는 남아 있다.
- PG.Dungeon.Layout1000Seeds 통과: 방 수·겹침·연결·필수 목표·시드 재현·장식 독립성·8~12개 기본 배치·잘못된 규격 차단.
- 실제 PIE 월드 100개 시드(101026 및 0~98) 모두 첫 시도 성공. 기본 배치 사용 0회. 내비게이션 완전 경로와 실제 캡슐 통과, 매 생성 후 컴포넌트 8개 유지 확인.
- 정의 누락 시 Failed, 생성 직후 취소 시 Cancelled 및 컴포넌트 0개, 이후 -2147483648 시드의 새 생성 Ready 복구 확인.
- 최초 로딩을 제외한 NullRHI PIE 반복 생성 관측값: 중앙값 0.203초, p95 0.297초, 최대 0.312초. 에셋이 로드된 검사 환경의 관측이며 패키지 생성 시간·프레임 성능 수용을 의미하지 않는다.
- 새 에디터 프로세스의 맵 재로드, 원본 테스트 맵 SHA-256 불변, 맵/테마 저장 성공 확인.
- 최종 쿼터뷰·전체 배치·방 사선 캡처 3장을 확인했다. 방별 바닥 패턴과 외곽 식생이 표시되며 이전 방향광 경고는 사라졌다. 현재 아트는 규격 확인용으로 반복이 강하고 담장 UV·방별 구성의 폴리싱이 필요하다.
- 최종 렌더 프로세스는 모든 캡처와 종료 로그 이후 3221225477(0xC0000005)로 반환했다. result.json의 render는 FAIL, render.json은 FAIL_SHUTDOWN이다. 앞선 렌더 실행은 정상 종료했지만 최종 버전의 정상 종료 통과로 대체하지 않는다. 기존 ForestRuins 렌더 기록에도 같은 종료 코드가 있으나 공통 원인은 미확정이다. 빌드·맵 저장·NullRHI 자동/실제 월드 검사는 종료 코드 0이며, 최종 전체 검증 결과는 렌더 종료 문제 때문에 FAIL로 유지한다.

P1: 방 진입·필수 목표 5개를 StageManager에 연결하고 기존 7회 강화와 적 총예산을 보존해야 한다. 보스 진행 게이트·봉쇄 해제·방별 스폰·분기 전리품이 남아 있다.

P2: 제작 방 모듈 변형, PCG 환경 배치, 발견형 미니맵, 카메라 가림 처리가 남아 있다. 현재 쿼터뷰·개요·사선 장면 캡처는 3D 액션 카메라의 직접 조작 검증을 의미하지 않는다.

P3: 레이아웃과 콘텐츠 버전 저장, 체크포인트 복원, 보상 트랜잭션 연결, 실패 주입 확대, Development 패키지 성능, 10개 시드 직접 완주 및 20분 연속 플레이가 남아 있다. 이 실행에서는 전체 고정 맵 전투 회귀 및 패키징을 수행하지 않았다.
