# GPU·셰이더·카메라 최적화 (2026-10-10)

## 적용 범위

- `ToonScreenOutline.hlsl`: 주변 스텐실이 대상 캐릭터가 아닌 경우 깊이 텍스처 2회 조회를 생략한다. 8방향 샘플, 외곽선 폭, 앞/뒤 가림 및 캐릭터 겹침 판정은 보존한다. 비활성 효과도 조기 반환한다.
- `ToonShading.hlsl`: 반사가 꺼진 재질은 반사 계산을 생략하고, 등방성/이방성 비율이 0/1일 때 사용하지 않는 로브를 계산하지 않는다. 중간 비율과 기존 SDF·헤어·상태 발광 수식을 유지한다.
- `DefaultScalability.ini`: Epic(`AntiAliasingQuality@3`)의 TSR 히스토리를 200%에서 150%로 조정한다. 실제 화면 해상도와 TSR 거부/필터 품질은 유지한다. 히스토리 픽셀 수는 기존의 56.25%이며 Cinematic은 엔진 기본 200%를 유지한다. 히스토리 해상도 감소는 극세부의 시간적 안정성에 영향을 줄 수 있다.
- `DefaultEngine.ini`: `r.HZBOcclusion=1`을 적용한다. 하드웨어 가림 쿼리 대신 보수적인 HZB 가림 판정을 사용한다. 아래 반복 측정에서 소폭 GPU 비용 증가와 교환해 프레임 p95를 크게 낮춘 후보를 채택했다.
- `PGDungeonEnvironment.cpp`: 페이드 중 전체 ISM 렌더 프록시 재생성을 제거한다. 설치 UE 5.8의 `SetCustomDataValue` → `CustomDataChanged` → `MarkRenderInstancesDirty` → `SendRenderInstanceData_Concurrent` 증분 갱신을 사용한다. 충돌과 페이드 값은 보존한다.
- `PGCharacterPlayer.cpp`: 카메라 페이드가 미치는 캡슐 전체를 감싸는 구로 먼 액터를 먼저 제외한다. 가까운 액터는 기존 캡슐 선분 거리 판정을 유지하고, 완전 숨김/복구 영역의 제곱근을 생략한다.
- `PGPlayerController.cpp`: 근처 액터의 부착물 배열을 재사용하고 프레임 내 메시 집합에 인라인 저장을 사용한다. 사망 후 충돌이 꺼진 적, 장비 탈착, 카메라 모드 전환 복구를 유지한다.

## GPU 측정

RTX 3060 Ti / 드라이버 581.29, 1920×1080, TSR, Screen Percentage 100, 강제 LOD1 Inori 50개, 에디터 PIE 애니메이션 장면. 각 단계 준비 8초·측정 12초. 다른 Unreal/게임/셰이더 컴파일 프로세스 오염과 본 움직임, 최종 CSV 저장, 종료 코드 0을 검사했다. 실제 AI 전투나 패키지 인증과는 별개다.

| 조건 | 전체 표현 반복 | GPU 평균 범위 | 반복 평균 | 프레임 p95 범위 |

셰이더만의 작은 차이는 반복 변동 범위와 겹쳐 유의한 단독 개선으로 확정하지 않는다. TSR 조정까지의 반복 평균 GPU 시간은 변경 전 대비 약 7.4% 감소했다. 최종 HZB 채택은 GPU 평균 약 0.42ms를 추가 사용하지만 프레임 p95가 29.78–32.10ms에서 15.95–18.80ms로 낮아졌다. 최종 GPU 평균은 변경 전보다 약 4.4% 낮다. 반복 3개 중 1개의 p95가 16.67ms를 넘고 p99는 16.89/39.00/17.70ms이므로 50캐릭터의 완전한 60fps 수용 완료를 주장하지 않는다. CSV `RenderThreadTime`은 거의 0이어서 CPU 병목 확정에 사용하지 않는다. 이번에 CPU trace를 새로 수집하지 않았으므로 가림 방식 변경의 관측 효과와 대기 원인 확정을 구분한다.

변경 전 기능 제거 비교에서 외곽선 후처리 0.21ms, 후처리+CustomDepth 0.52ms, 캐릭터 그림자 1.11ms의 GPU 차이를 관측했다. 이는 병목 진단이며 기능 제거를 생산 설정으로 채택하지 않았고 절감량을 합산하지 않는다. 첫 전체 표현 표본의 TSR은 3.29ms, ShadowDepths 1.92ms, ShadowProjection 1.22ms였다.
