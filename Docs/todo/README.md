# 프로젝트 지침 정합성 개선 계획

분석일: 2026-09-19. 상태: 1·2단계 구현 및 검증 반영. [실행 보고서](Stage12_Implementation_Report.md)에서 완료 범위와 잔여 검증을 확인한다.

후속 구현: [3·4단계 보고서](Stage34_Implementation_Report.md)에 파밍·빌드·저장, 모듈 경계 정리, 반복 재시작 및 부하 측정 결과를 기록했다. 전체 상용 품질 수용 완료와 구현/자동 검사 통과를 구별한다.

## 최초 분석 시점 판단

현재 프로젝트는 **모듈화된 전투·웨이브 액션 프로토타입 기반**이다. GAS 어빌리티, 몽타주·히트 리액션, 데이터 테이블, 적 스킬 선택, 투사체/데미지 플로터 풀링은 재사용 가치가 있다. 다만 지침의 **쿼터뷰 액션 파밍 ARPG**를 이루는 조작, 획득·장비 성장, 저장·재도전 연결은 추가 작업이 필요하다. 기존 기반을 유지하면서 한 구간의 완성도를 높이는 접근을 제안한다.

## 최초 분석 범위와 한계

- `AGENTS.md`, `CLAUDE.md`, `PROJECT_OVERVIEW.md`, 실제 `.uproject`, Target/Build 설정과 Source의 주요 실행 경로를 대조했다.
- `Documentation/StageManager_Improvement_Guide*.md`는 이전 설계 참고 자료다. 코드의 구현 완료 증거로 취급하지 않았다.
- `Content`에는 개발 맵과 Blueprint/DataCenter 에셋이 있다. 바이너리 에셋 내부, BP 오버라이드, 실제 시각 품질은 에디터에서 검증하지 않았다. 아래의 “미확인”은 게임 전체에 기능이 없다는 단정이 아니다.
- 빌드, PIE, 패키지 실행, 성능 측정은 수행하지 않았다. 정적 결함과 런타임 재현 필요 항목을 구별한다. 이 문단은 최초 분석 시점의 한계이며 이후 구현·실행 결과는 실행 보고서에 별도로 기록한다.
- 싱글 플레이 PC, 키보드·마우스를 첫 검증 대상으로 가정한다. 출시 플랫폼과 멀티플레이 요구는 확정되지 않았으므로 별도 대규모 구현을 포함하지 않는다.

## 권장 마일스톤

1. **M0 실행 가능한 기준선**: 01, 02, 10의 데이터 사전 검사, 11의 스모크 체크. 잘못된 데이터나 보상 대기로 게임이 멈추지 않는다.
2. **M1 전투 한 구간**: 03~05, 08의 기본 적 구성. 일반 적 2종과 정예 1종, 기본 공격과 액티브 2개·회피로 조작과 타격을 검증한다.
3. **M2 파밍 한 바퀴**: 06, 07, 09. 10~15분 구간에서 처치→획득→비교/장착→전투 변화→저장/재시작을 검증한다.
4. **M3 확장 준비**: 10, 11의 패키지·부하 게이트와 12의 필요한 경계 정리. 다음 콘텐츠는 코드 복제 없이 데이터로 추가한다.

지금은 대형 패시브 트리, 제작 경제, 거래/온라인, 절차 생성 월드, 다수 직업, 대규모 보스군을 보류한다. 웨이브 스테이지는 파밍 루프 검증용 구간으로 유지할 수 있으며 장르 변경을 뜻하지 않는다. 기존 보상 카드는 보너스 선택으로 활용하되 장비 획득을 대체하지 않도록 한다.

## 공통 완료 규칙

각 건은 코드·데이터·에셋 연결, 플레이 가능한 확인 경로, 디버그 수단, 예외 처리, 해당 문서의 수용 기준을 함께 완료한다. 후속 구현 시 기존 BP 참조와 데이터 이관을 확인하며 `PG` 명명과 기존 모듈 책임을 따른다. 각 수용 기준은 해당 건의 구현 반영과 실행 보고서에 통과 근거가 명시된 경우에만 완료로 본다.
