# 09. 사망·재도전·저장/로드 수명주기

우선순위 P1 / 상태 구현·반복 재시작 검증 반영 / 선행 02, 06, 07 / 규모 대

## 현재 근거

`PGAbilityPlayerDeath::EndAbility`는 애니메이션 정지와 캡슐 충돌 비활성화를 수행한다. `PGGameModeStage::EndGame`에는 종료 처리 TODO가 있다. Source/Plugins에서 SaveGame 구현은 확인하지 못했다. BP의 재시작/저장 경로는 별도 확인 대상이다.

## 목표와 정책 제안

첫 버전은 로컬 프로필 하나와 구간 체크포인트를 사용한다. 확정된 아이템·장착·스킬 성장과 해금 구간은 영속, 살아 있는 적·투사체·시전 중 상태는 재구성 대상으로 나눈다. 사망 시 해당 구간 처음부터 재도전하며 보상 지급 토큰은 중복 지급을 막는다. 사망 손실 경제는 후순위다.

## 최소 작업

1. UPlayground의 게임 흐름에서 진행/보상/사망/재도전/종료 전이를 관리한다. PGActor는 입력·충돌·몽타주·태그·타이머를 정리한다.
2. 영속 데이터 소유자를 Pawn과 분리한다. 버전, 아이템 고유 ID·옵션, 장착, 스킬, 진행·보상 확정 상태를 저장한다. UObject 포인터는 저장 계약에 넣지 않는다.
3. 지급과 저장 경계를 정의한다. 성공 저장 전 종료 시 이전 체크포인트 복귀 여부를 명시하고 부분 지급 상태가 저장되지 않게 한다.
4. 저장 실패·손상·버전 차이에 백업/복구 선택을 제공한다. 알 수 없는 아이템/스킬 ID는 기록하고 대체/보관 정책을 적용한다.
5. 로드→데이터 준비→ASC 초기화→장비/스킬 복원→HUD 갱신→입력 허용 순서를 지킨다.

## 수용 기준

- 사망/재도전 20회 후 체력·충돌·입력·카메라·태그·UI가 정상이고 구독이 누적되지 않는다.
- 획득·장착·보상 선택 직후 저장/프로세스 재시작에서 중복/유실 정책이 일관된다.
- 손상 파일·누락 ID·저장 실패 시 크래시 없이 복구 가능하며 기존 정상 저장을 유지한다.
- 맵 전환 뒤 이전 투사체/보상 타이머가 새 플레이어에 영향을 주지 않는다.

디버그: 저장 버전/체크포인트/토큰 조회, 개발 전용 저장 실패 주입. 후순위: 클라우드·다중 캐릭터·전투 도중 완전 복원.
