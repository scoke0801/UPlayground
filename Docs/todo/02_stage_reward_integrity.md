# 02. 스테이지 진행과 보상 확정의 무결성

우선순위 P0 / 상태 구현 반영·잔여 검증 있음 / 선행 01 / 규모 중

## 코드에서 확인한 문제

근거: `Source/PGActor/Manager/PGStageManager.cpp`.

- `BeginPlay`에서 OnSpawned 등록 결과를 `OnActorDiedHandle`에 덮어쓴다. 해제에 쓰는 두 핸들의 대응이 깨진다.
- `OnActorDied`의 유효성 검사 뒤에 블록/return이 없어 바로 다음 Remove만 조건부로 실행된다. 정상 사망에서도 카운트 감소와 목록 제거가 일치하지 않는다.
- `SelectNextMonsterToSpawn`은 시작 시간을 현재 시각과 스폰 수에서 역산한다. 첫 지연 스폰이 실제 경과 시간으로 해제되지 않을 수 있다.
- 즉시 스폰 while문은 대기열이 남고 진전이 없으면 탈출하지 못할 수 있다. 대기열 수량은 스폰 성공 전에 감소하므로 실패 시 예정 수량과 실제 생존 수가 어긋날 수 있다.
- `ShowRewardSelection`은 지역 핸들의 1.5초 타이머로 보상 선택을 자동 완료한다. `PGUIWindowRewardSelect::SelectReward`는 빈 함수다.
- OnSpawned 경로와 배치 경로 모두 목록/수량에 관여한다. 실제 이벤트 발신 경로를 전수 확인하여 일반 적·소환 적의 중복 집계 여부를 재현해야 한다.

## 목표 경험

정해진 적을 처치하면 보상을 선택하고, 지급 성공 후 다음 구간으로 이동한다. 실패·중복 이벤트·데이터 오류로 진행이 무한 대기하지 않는다.

## 최소 구현

1. 이벤트별 핸들과 해제를 분리하고 유효하지 않은 사망 알림은 즉시 반환한다. 현재 스테이지에 등록된 적의 첫 사망만 처리한다.
2. 실제 StageStartTime을 저장하고 예정/대기/생존/처치 수를 명확히 구분한다. 소환 적의 클리어 포함 정책을 데이터로 지정한다.
3. 스폰 성공 후 수량 확정, 제한된 실패 재시도, 재시도 초과 시 중단/실패 UI를 정의한다. 지연 대기는 타이머로 처리하고 즉시 스폰 루프에는 진전 없는 반복을 차단한다.
4. 보상 상태에 선택 토큰을 발급한다. UI 선택 요청→유효성 검사→한 번 지급→완료 이벤트 순서로 확정한다. UI 닫기나 중복 클릭은 지급 완료가 아니다.
5. 테스트 자동 통과를 일반 플레이에서 제거한다. 소유 가능한 보상 타이머를 쓰고 사망·재시작·EndPlay 때 정리한다. 마지막 스테이지의 완료 화면을 연결한다.

소유: PGActor는 진행 상태, PGUI는 표현/선택 요청, PGData는 보상 정의, PGMessage는 결과 전달. 장비 지급 구현은 06에 연결하되 먼저 검증용 스탯 보상으로 완료 이벤트를 검증할 수 있다.

## 수용 기준

- 0초/지연 스폰, SpawnBatchSize 0, 누락 클래스, 스폰 실패에서도 프레임 정지 없이 성공/실패 상태가 결정된다.
- 동일 적 사망 2회·무관한 적 사망·소환 이벤트에도 집계가 정확하고 보상이 1회만 열린다.
- 선택하지 않으면 자동 진행하지 않고, 연속 클릭 20회에도 지급 1회·진행 1회다.
- 보상 중 사망/재시작/맵 종료 후 이전 콜백이 새 스테이지를 변경하지 않는다.

디버그: 단계·토큰·예정/생존 수·스폰 실패 이유 표시. 후순위: 분기형 스테이지와 복잡한 보상 연출.

## 2026-09-19 구현 반영

구독 핸들 분리, 지연 스폰/0초 간격의 유한 배치, 스폰 실패 상한, 처치 중복 제거, 소환 포함 정책, 보상 토큰과 1회 지급, 완료·실패·재시작 화면을 구현했다. 현재 지급 범위는 Stat 보상이며 3개 행과 3개 스테이지 풀을 연결했다. 아이템·스킬 보상은 후속 파밍 작업에서 확장한다.
