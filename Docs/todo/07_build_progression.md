# 07. 데이터 기반 스킬 로드아웃과 빌드 성장

우선순위 P1 / 상태 최소 성장 구현·확장/밸런스 수용 검증 남음 / 선행 04, 06 / 규모 중

## 현재 근거

`PGCharacterPlayer::PossessedBy`가 100, 110~115, 10000, 20000 스킬 ID를 슬롯에 직접 등록한다. `PGSkillDataRow`는 몽타주·연계 스킬·쿨타임·범위 등을 노출하지만 빌드 성장 계약은 추가가 필요하다. RewardSkill/RewardStat 행은 식별자 중심의 초기 형태다.

## 목표와 최소 범위

초기 로드아웃·해금·성장·장비 변경을 데이터로 처리한다. 첫 콘텐츠는 기본 공격, 액티브 2개, 회피와 두 가지 빌드 방향으로 제한한다. 예: 빠른 연속 공격과 느린 범위 강타. 단순 공격력 차이 외에 빈도·범위 중 하나가 체감되도록 한다.

1. PGData에 시작 로드아웃, 스킬 단계별 계수/비용/쿨다운, 해금 조건, 허용 슬롯을 정의한다. 기존 ID를 데이터로 이관한다.
2. PGAbilitySystem은 스킬 변경 시 기존 부여 핸들/효과를 회수한다. PGActor의 SkillHandler는 슬롯 매핑 책임을 유지하되 수치의 중복 원본을 만들지 않는다.
3. 06의 장비 옵션과 스킬 태그 조건을 연결하고 중첩/배타 규칙을 최소한으로 정의한다.
4. PGUI에서 다음 성장으로 변하는 값, 장착 불가 이유, 선택 결과를 보여준다. 보상 취소/실패는 02의 확정 규칙을 따른다.

## 수용 기준

- C++ 수정 없이 시작 스킬 교체와 기존 스킬의 성장 단계 추가가 가능하다.
- 중복 보상·재빙의·로드 후 어빌리티가 중복 부여되지 않는다.
- 두 빌드를 같은 적/같은 시간 조건으로 비교해 플레이 차이와 DPS/생존 지표를 기록한다.
- 잘못된 ID/태그/단계는 10의 검사로 차단되며 저장된 구버전 ID의 대체 정책이 있다.

디버그: 해금·레벨·로드아웃 변경, 활성 효과 목록과 피해 집계. 후순위: 대형 패시브 트리, 다수 직업, 재분배 경제. 밸런스 값은 검증 전 확정치로 취급하지 않는다.

## 2026-09-19 구현

C++ 시작 ID를 카탈로그로 이관하고 두 방향/두 단계의 스킬 슬롯·쿨다운·누적 클리어 해금·빌드 선택 저장을 구현했다. 무기 교체와 별도로 슬롯의 마지막 사용 시각을 보존한다. 기존 슬롯별 어빌리티를 재사용하며 재빙의에 따른 중복 부여를 방지한다. 피해 계수/비용 단계, 장비 태그 조건과 두 빌드의 실제 DPS/생존 비교는 완료 범위에 포함하지 않는다. [3·4단계 보고서](Stage34_Implementation_Report.md)에서 실행 근거와 한계를 확인한다.
