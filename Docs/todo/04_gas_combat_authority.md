# 04. GAS 중심 전투 수치와 피해 처리 통합

우선순위 P1 / 상태 구현 반영·잔여 검증 있음 / 선행 01 / 규모 대

## 현재 근거와 영향

- `PGAtrributeSet.cpp`는 체력·분노·공격·방어를 초기화하지만 `PostGameplayEffectExecute`가 비어 있다.
- `PGCharacterPlayer::OnHit`은 `PGStatComponent::CurrentHealth`를 직접 변경하고 UI 메시지를 보낸다. `PGStatComponent`에는 별도 StatMap과 피해 공식이 있다.
- 피해 공식에 방어 상수 100, 기본 치명 배율 1.5가 존재한다. `PGAbilityHitReact`가 OnHit을 호출하므로 피격 연출 경로와 피해 적용이 결합되어 있다.

복수 수치 저장소가 존재한다는 것은 확정 사실이다. 모든 BP에서 실제로 값이 충돌하는지는 에디터 확인이 필요하다.

## 목표와 설계

최종 전투 수치의 원본을 ASC/AttributeSet으로 통일한다. 기존 StatComponent는 데이터 초기화·조회 어댑터로 단계적으로 축소한다. 체력·피해·회복부터 이관하고 모든 스탯을 한 번에 재작성하지 않는다.

1. PGShared에 피해 결과/원인 식별 계약을 정의하고 PGAbilitySystem이 판정과 적용을 소유한다. 근접·투사체·장판이 같은 적용 경로를 사용한다.
2. 피해 적용과 HitReact 표현을 분리한다. 경직 면역이어도 피해는 적용되고 사망 이벤트는 한 번 발생한다.
3. PGData에 피해 계수·방어 커브·치명 규칙과 허용 범위를 노출한다. GE로 장비/버프 변경과 제거를 처리한다.
4. 최대 체력 변화 시 현재 체력 정책, 음수/0 입력, 중복 충돌, 유효하지 않은 공격자, 회복·사망 경쟁을 정의한다.
5. HUD는 확정된 Attribute 변경과 전투 결과를 구독한다. 과도기에는 양방향 동기화를 금지하고 한 방향 어댑터만 둔다.

## 이관과 수용 기준

- 대표 근접·투사체·장판 각 1개를 이관하고 기존 GE/BP 직접 체력 쓰기를 조사한다.
- 동일 데이터의 예상 피해·치명·방어·회복 사례가 자동 검증된다. 확률은 고정 시드/강제 판정으로 재현한다.
- 장비 장착→해제 100회 후 수치가 원복되고 HUD/체력/사망 판정이 일치한다.
- 최대 체력 0·무효 공격자·이미 죽은 적에 추가 타격 시 크래시/중복 사망이 없다.

디버그: 기초→장비→버프→최종 수치와 피해 계산 내역. 후순위: 속성·저항·지속 피해의 대규모 확장, 네트워크 예측. 리스크: Attribute 타입 이름 변경은 이 작업의 필수 조건이 아니며 에셋 호환성을 우선한다.

## 2026-09-19 구현 반영

GAS AttributeSet을 체력·공격·방어·치명타·회복·이동속도의 권위로 두고 기존 StatComponent는 조회 어댑터로 전환했다. 피해/회복/보상은 GE, 장비는 교체 가능한 Infinite GE로 반영한다. 피격 어빌리티 유무와 피해 확정을 분리했다. 피해 경계와 장비 100회 적용·해제 자동 테스트가 통과했다. 동적 GE는 현재 싱글 플레이 범위이며 네트워크 복제 지원을 뜻하지 않는다.
